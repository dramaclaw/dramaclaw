# 历史未归属改动隔离区

**状态**：已阻塞
**最后更新**：2026-09-18
**基线**：`38484897`；这些文件已在当前工作区变脏，但现有六条业务台账没有足够证据认领
**认领者**：无；禁止实现，只允许来源审计
**相关文档**：无
**相关分支 / PR**：待逐文件用历史、diff 与相关远端分支确认

## 目标

保护无法可靠归入现有工作线的历史脏文件：在来源、意图和验证证据明确前，任何 AI 都不能覆盖、
格式化、删除或顺手修复它们。最终每个文件必须迁入一个真实工作线，或经证据确认后安全废弃。

## 非目标

- 不把“看起来相关”当作归属证据，不替六条业务线扩大范围。
- 不在本线实现产品功能；本线只做取证、分类和迁移。
- 不删除 `_to_delete/`，目录名不是删除授权。

## 现状与证据

- `git status --short -uall` 显示一批修改未出现在六条台账的写入边界中。
- 部分文件可能来自更早会话、已合并远端分支的旧副本或尚未建账的工作线；当前没有可靠会话记录。
- 把它们硬塞进最相似的工作线会制造错误所有权，因此先 fail closed 隔离。

## 写入边界

精确路径见 `docs/agent/claims/legacy-unassigned-diff.toml`。全部是保护性 `exclusive` 或 `read-only`
认领；状态为「已阻塞」，所以 guard 不会允许任何会话 acquire 本线进行写入。

## 协调与冲突

- 某文件迁入真实工作线前，先在目标台账补现状证据、方案和验收，再同时移动 TOML claim。
- 若与远端提交内容一致，记录提交和 patch-id / diff 证据后再决定丢弃本地副本，不能凭肉眼直接 restore。
- 若属于全新工作线，从模板建账；不要让本隔离区永久变成“杂项任务”。

## 实施方案

1. 按文件簇审计：画布基础交互、freezone 外壳、会话流、后端 video node / home placement。
2. 对每簇查 `git log --all -- <path>`、相关分支 diff、当前调用链和测试，写出来源结论。
3. 有明确归属的移动 claim 并在目标台账记录；无价值且确认可丢弃的请求用户批准后再做可恢复清理。
4. 所有条目迁出后把本线标「已完成」并归档。

## 风险与回退

- 风险：误归属会让后续 AI 合法覆盖原作者改动；误删除则可能永久丢失未提交实现。
- 回退：本线不做业务写入；分类错误时把 claim 移回本隔离区并恢复对应审计记录。

## 验收标准

- [ ] TOML 中每条路径都有来源提交 / 会话 / 调用链证据。
- [ ] 每条路径迁入明确工作线或经用户批准安全清理。
- [ ] `python3 scripts/agent_guard.py check` 不再需要本隔离工作线且全绿。
- [ ] 没有执行整树 restore、自动 stash 或基于目录名的批量删除。

## 已定下来的决策

- **未知改动默认保护，不默认丢弃**——缺上下文时，保留可逆性比猜测归属更重要。
- **目录名 `_to_delete` 不构成删除授权**——只有用户明确批准和目标清单核对后才能删除。
- **本线不能进入「执行中」做产品开发**——它只能做只读审计和 claim 迁移。
