# 项目分享用户搜索与错误提示

## 范围

修复 `frontend/src/components/projects/share-project-dialog.tsx` 的项目成员分享
体验。修改位于 DramaClaw 仓库共享的前端源码，实际行为仅适用于启用项目分享能力的
EE/控制面运行时；CE 运行时仍保持现有的入口隐藏和接口排除策略。

不修改后端授权规则，也不修改独立的 `supertale-admin-fe` 管理后台仓库。

## 目标行为

1. 用户搜索请求发送前，去除输入中用于拼音分词的 ASCII 单引号（`'`）。输入框保留
   用户原始输入，搜索和选中结果使用规范化后的查询值。
2. 查询满足最小长度、请求成功且没有可选结果时，在输入框下方显示就地提示：该用户
   可能不在本项目的可分享范围内。
3. 只有用户从下拉搜索结果中选中账户后，才允许提交新增分享请求。直接输入用户名而
   未选中结果不能触发接口调用。
4. 新增分享请求失败时，按后端响应分类：
   - `403` 且 `detail.code` 为 `project_share_scope_mismatch`：提示用户不在可分享范围。
   - `404`：提示用户不存在。
   - 其他情况：保留现有通用失败提示。
5. 为以上交互与错误分流增加 Vitest 回归测试，并为中英文翻译文件添加对应词条。

## 实现边界

- 查询规范化放在 `useUserSearch`，使请求参数与 React Query 缓存键保持一致；弹窗仍保存
  原始输入以避免编辑体验发生变化。
- 弹窗只提交 `selectedUser.username`，不再回退到原始查询文本。
- 错误体从 Ky 的 `HTTPError.response` 安全读取，不依赖后端的自然语言错误文案。
- 不改变现有分享人数上限、成员列表加载保护、角色选择或撤销分享逻辑。

## 验收与验证

- 输入 `huang'jiao` 时，用户搜索接口接收 `huangjiao`。
- 搜索无结果时显示范围提示，且未选中用户不能发起分享请求。
- 选择用户后可正常提交；范围不匹配、用户不存在和未知错误显示各自正确的 toast。
- 定向运行 `frontend/src/__tests__/components/projects/share-project-dialog.test.tsx`，并运行
  前端类型检查/构建。
