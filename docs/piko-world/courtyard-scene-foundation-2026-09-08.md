# 初遇庭院：场景基础复盘与实施草案

状态：规划，尚未实施。基于当前 base.png、地图 JSON 与 Pixi 运行时代码检查；几何位置结论仍需叠图及实走验证。

## 当前事实

- 母版是 2048×1152 完整平面图；运行时整体 contain 缩放，没有角色跟随镜头。
- 当前 navigation 有 3 块可走区、13 个碰撞区、3 个出生点、4 个出口；不等于这些区域已经精确验收。
- 玩家使用 WASD/方向键；指针点击仅聚焦地图，没有点击寻路。速度 150 地图像素/秒，碰撞半径 8，移动按不超过 3 像素的子步分轴处理，允许沿障碍滑动。
- 角色按脚下 y 排序；occlusion.occluders、environment.effects、environment.audioZones、interactions.interactions 均为空。镇长与社交交互在专用代码中实现。
- Canvas 当前只消费底图和导航；有遮挡/环境 schema 不代表渲染器已支持。居民出生坐标仍由 actor 默认值提供，未消费地图 spawnPoints。
- 两套点在多边形内判断对边缘处理不同；后续应统一几何核心和边界语义。当前半径采样是近似检测，薄障碍、凹角、拼接可走区需要专项验证。

## 地图体验目标

先做出可读、可走、前后关系可信的庭院，再增加动态密度。自由移动包含连通的道路与合理草地区域，不意味着水面、花坛和所有画面边缘都能通行。

第一条验收路线：南入口 → 拱门 → 喷泉绕行 → 大厅台阶 → 东侧树下/长椅 → 河桥 → 返回西侧告示牌。另验证北路和可进入草地区域。

以脚下接触点为世界坐标；角色身体高度用于显示，脚下小圆或椭圆用于碰撞。碰撞体描述物体落地占用范围，遮挡轮廓描述其可见形状，两者分别标注。

## 逐类空间规则

| 对象 | 通行/碰撞 | 遮挡与动态 |
| --- | --- | --- |
| 大厅 | 基座/墙体不可穿；台阶与门前区域单独确认；没有室内前门口触发交互 | 屋檐与需要覆盖人物的上部独立；长建筑不能仅依赖一个中心 y |
| 喷泉 | 按池沿落地轮廓阻挡，四周可绕 | 池沿、雕塑与水体有不同前后关系；水动不改变碰撞 |
| 欢迎拱门 | 两根柱脚阻挡，中央门洞可通过 | 横梁、柱体需要独立深度关系；不可整座永远压在人前 |
| 大树 | 树干/根部阻挡，可进入的树荫不阻挡 | 树冠遮挡身体；强遮挡时仅对本地玩家提供轻轮廓或局部透明反馈 |
| 长椅/告示牌/路灯 | 根据支撑位置校准，不沿画面全高画墙；座位另设朝向和交互距离 | 上部可遮挡角色；静态灯体与发光区分离 |
| 围墙/花坛 | 实体边界阻挡，确认缺口确实可通 | 墙顶、灌木可局部挡住腿部 |
| 河道/桥 | 水不可走，桥面单独通行；桥栏不可穿 | 桥栏分前后，水动态严格限制在水面 |

当前东侧长椅 collider 的 y 范围为 430–495，而母稿中长椅视觉位置更低，是优先叠图核对点，不直接凭目测修改坐标。现有建筑和告示牌等碰撞区域也需要逐物校准。

## 分层与素材策略

保留原母稿作为对照和回退。建立地面、地面效果、按深度排序的物件/角色、空中效果、界面层。每个场景对象关联自己的碰撞体、遮挡切片、排序锚点和动态配置。

静态遮挡可以先用原位精确切片覆盖原图验证，但缩放边缘必须检查重影。发生移动、透明或变形的树冠、草簇、水流不能直接叠在原图同一物体上：需要清理该处底图并补齐被遮住的地面，再叠加独立元素，避免双影和露洞。

优先做拱门、东侧大树、喷泉三个小样，验证单一深度线能处理什么，哪些对象需要拆件。不要一次切完整张图。人物姓名、气泡与被遮挡状态要一起设计，避免身体消失、巨大气泡仍暴露位置。

## 动态与生命感

1. 持续环境：喷泉水流/涟漪，河面局部反光，稀疏草叶与树梢摆动。树干保持稳定，共享风向但各簇相位不同，避免整棵树像贴纸摇晃。
2. 偶发事件：少量飞鸟穿越、小片落叶、间歇虫鸣；随机等待而非同一轨迹短周期重复。鸟在空中层，影子可选且落在地面层。
3. 地面动物：先做一种动物的一个个体，如树边松鼠，具有等待、短距离觅食、察觉靠近、退避与回归行为。使用动物活动区和障碍查询，不能穿墙、下水或瞬移；第一版不作为玩家硬碰撞体。
4. 水声按喷泉/河岸距离平滑变化，保持 BGM、脚步、通知的既有音量层次；不要同时堆叠连续虫鸣、鸟鸣和风声。

建议初始只展示一个地面动物、少量偶发飞鸟，具体密度通过实机体验确定。生命感来自不同节奏、合理活动位置和对玩家的轻反应，而不是全屏持续运动。

## 实施顺序与产物

### A：空间标注与调试工具

产物：基于母图的可走区/硬碰撞/遮挡/互动/动态区叠图，以及运行时可开关的脚点、碰撞体、深度线和坐标显示。统一坐标、物件 ID 和保存格式。先校准角色尺度、速度与脚点，再逐区域描边；不凭聊天中的截图估最终坐标。

验收：主要路线连通；狭窄通道、斜向擦边、低帧率、地图边缘不穿透不卡住；自然草地能按设计进入。摄像机先保留全图，测试小屏可读性后再决定跟随/缩放。

### B：遮挡小样与底图修复

产物：拱门、大树、喷泉的小样切片、局部清底与数据加载/排序支持。

验收：人物沿物体四周行走前后关系正确；远近缩放无接缝、双影；树下人物仍可定位；静止时与母稿观感一致。

### C：基础环境动态

产物：喷泉、河面、两三处草木动态及空间环境声。共享场景时钟；离屏或页面隐藏时暂停无关更新，减少动态模式保留完整通行与交互。

验收：不扭曲建筑和岸边；循环接缝不突兀；动静结合；在约定设备与视口记录帧耗、资源体积和内存。性能预算待实测后确定，不预先承诺帧率。

### D：生态与地图出入

产物：一种动物行为与低频飞鸟，出生点/出口配置真正接入运行时。没有完成的目标地图保持明确边界；所有可用出口验证目标出生点安全且可达。

验收：动物不穿障碍；不阻塞玩家；出入地图不闪白、不把人物放进碰撞体；多次进入退出不叠加 ticker、事件监听或音源。

### E：提炼可复用规范

把通过验证的对象、导航、遮挡、环境、生态和交互配置固化为带版本的地图包。扩展现有 schema，不另建平行配置体系。复用的是坐标规则、组件、调试工具和验收流程；其他地图的几何和特殊深度仍逐图标注。

先统一点/圆与多边形判定，并让玩家、动物、出生安全检测共用空间查询。点击寻路和更大的地图再评估导航网格；当前无需为了行走碰撞立即引入重型物理引擎。角色坐标当前每次移动都会触发 React state 更新，动态对象增加前应将高频显示位置留在渲染层，界面状态按需同步。

## 首个实际工作节点

下一步先完成 A 的空间标注与叠图调试，输出可逐区讨论的初遇庭院空间蓝图；随后选择拱门作为第一个碰撞与遮挡联合验证对象。在这两个节点通过前，不批量制作动物和树木动画。

## 调试工具第一版（已接入开发环境）

进入初遇庭院并完成加载后，左下角可见「场景调试」。编辑模式用下拉框或点击区域选择对象，拖动白点修改顶点；双击区域内部在最近边插入一个顶点，可撤销、重做及新增矩形区域。绿色代表可走区，红色代表碰撞区，黄色小圈标记角色脚下碰撞范围。

「应用并试走」只更改当前场景内存中的导航数据；「退出调试」恢复原配置。编辑/试走不写服务器或源文件。保存草稿写入当前浏览器的地图专属 localStorage，导出下载 JSON，均保留原地图包。轮廓自交、退化、重复 ID 或越界时禁止应用与导出；当前玩家被草稿阻挡时不进入试走。

本版尚不包含镜头缩放/平移、整区拖动、遮挡切片编辑、区域命名与碰撞类型编辑，也未重新校准正式地图轮廓。现有叠图是第一轮标注底稿。自动化已覆盖编辑应用/退出恢复和几何校验；仍需在真实画布中进行拖拽与路线实走验收。

### 碰撞区编辑方式调整

按最新讨论，编辑草稿采用「地图矩形边界内默认可走，碰撞区阻挡」规则。可走区改为自动生成的整图区域，不再手工编辑；旧草稿载入时保留碰撞区并转换通行范围。新规则在应用并试走时生效，正式地图暂不覆盖，待补齐河岸、林地和墙体边界后再验收落盘。

拖动区域内部可整块移动，拖动顶点改形状；整块移动遇地图边缘会限制整体位移，保持形状。选中碰撞区后按 Cmd+D / Ctrl+D 或点击「复制区域」会建立独立副本并错开 24 地图像素。复制和移动可撤销；输入控件内不接管复制快捷键。
