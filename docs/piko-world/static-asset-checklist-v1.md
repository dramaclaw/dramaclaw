## 生产规则

- 先逐项生成并确认全部源图，不在生成过程中抠图。
- 需要后续抠图的概念表和独立素材统一使用纯洋红 `#FF00FF` 背景；背景必须完全平坦、无渐变、纹理、投影或环境反光。禁止使用会与白色高光、深色轮廓和绿色服装混合的浅灰、白、黑或绿幕背景。
- 同一素材未确认前不得入库；互不依赖的地图母稿可以并行生成，需要方向稿时使用已确认正面图作为唯一身份参考。
- 全部源图确认后，由用户统一处理透明背景并一次性回传。
- 回传后统一完成尺寸、限色、像素清理、轴心、分层、命名和入库。
- 夜间环境不重复生成整套蓝色素材；使用中性资产、运行时场景调色及少量独立发光状态。
- 区域母稿直接作为游戏基础画面，不切成通用地块重建；只派生碰撞、遮挡、交互、动态和光照需要的图层与数据。
- 独立派生图层必须与母稿使用相同像素坐标和原点；需要动画的固定内容先去重，再叠加运行时效果。
- `piko-world/art/reference/` 中的封版母稿保持只读，游戏运行版及派生层使用独立目录和版本，不覆盖视觉基准。

### 角色透明源稿回传规格

- 格式：RGBA PNG，真实透明背景；禁止把棋盘格、白色、灰色或黑色背景烘焙进图片。
- 尺寸：保留生成原图尺寸，当前镇长昼夜稿统一为 1600×1600 px；禁止提前缩放、像素化、锐化或限色。
- 对齐：昼夜稿使用完全相同的画布、角色尺寸、水平中心和脚底位置；不得分别自动裁切紧边。
- 内容：每个文件只保留一个完整角色及其穿戴／手持道具，四周留有透明安全边距，不得裁切叶片、书本、提灯或脚。
- Alpha：角色外部为全透明；允许干净的半透明抗锯齿边缘，但不得残留灰边、白边、黑边、投影或背景色污染。
- 夜间提灯：只保留灯具和灯芯内部暖色，不保留外部大面积光晕；运行时光照独立实现。
- 色彩：优先 sRGB，不主动改变亮度、饱和度和颜色配置。
- 文件名：`piko-mayor-day-transparent-v1.png`、`piko-mayor-night-transparent-v1.png`。

## 不需要用户生成的内容

- 角色脚底阴影：统一用代码或确定性像素模板生成。
- Piko 镇长待机帧：不单独生图；在昼夜 SOUTH 母帧像素化后，确定性制作呼吸、眨眼、叶片轻摆及夜间提灯微光帧，避免逐帧生成造成角色漂移。
- 夜间全局蓝色调、环境暗角和灯光范围：由运行时渲染处理。
- 对话框、交互提示和通用地图 UI 使用 HTML/CSS 或项目图标体系实现；H01 世界控制图标、H02 聊天三段式皮肤与 H03 居民选择三段式皮肤是已确认的主题化视觉层，其行为、Tooltip、文字、焦点与状态仍由 DOM/CSS 承载。
- 碰撞区、出生点、导航网格和遮挡层：属于地图数据，不是生图素材。
- 行走和交互动画帧：行为需求与静态母帧通过实机验证后再制作；首版固定镇长仅制作 SOUTH 待机循环。
