# Piko 世界地图规划 v1

状态：十五张区域母稿及其区域切换标题均已入库；当前以“预渲染母稿＋语义数据＋局部动态”方案实现初遇庭院可运行切片，并已用初遇庭院验证通用黑场标题过渡。

## 核心原则

- Piko 小镇不是任务驱动的传统游戏世界，而是供用户长期停留、独处、放松与自然交流的共享空间；每张地图即使移除任务和交互仍须具备独立、耐看的景观价值。
- 地图以自然风景的美感为首要视觉目标；呼吸感来自大尺度留白、疏密节奏和远近层次，生命感来自光、水、风与植被的自然关系，不以堆叠装饰、设施或玩法节点制造丰富度。
- 初遇庭院是 Piko 小镇的中央起点，不是孤立地图或世界边界。
- 每张区域母稿直接作为地图基础画面，原生 `2048×1152` 像素对应地图本地坐标；32 px 仅作为尺度和通行测量参考，不再要求将画面重建为地块图集。
- `piko-world/art/reference/` 中的封版母稿保持只读；局部去重、遮挡切片和动态蒙版均作为运行时派生资产另存，不覆盖视觉基准。
- 小镇连续性由已封版母稿、统一角色尺度、镜头规则和跨区出口共同保证；只有遮挡、动画、发光或交互所需内容才从母稿派生独立图层。
- 各区域使用独立本地坐标，通过明确出口连接；切换时预载目标区域并保持角色朝向与入口语义连续，不强制不同母稿边缘逐像素拼接。
- 日夜共用中性基础素材；全局夜色、暗角和光照范围由运行时实现，只为窗户、门灯、路灯等制作可对齐的发光状态。

## 小镇连续性契约

- 共用色彩：奶油白墙面、深海军蓝／青绿色屋顶、暖木、金色五金、森林绿植被、砖红和紫色点缀。
- 共用道路：主石板路始终保持同一宽度与铺装节奏；支路可切换为碎石、木桥或土路。
- 共用建筑语言：一至两层小体量、清晰门窗、非对称屋顶、克制的叶片／灯光徽记；禁止突然出现现实摩天楼或完全不同的文明尺度。
- 共用尺度：门、长椅、栏杆和摊位均以 56 px 人类居民为尺度依据；所有场景概念不得随意放大角色或建筑。
- 共用密度：保留清晰通行区和必要连接，以疏密节奏形成可停留空间，避免巨大空广场或装饰塞满可行走区域。
- 共用通行：以母稿像素坐标测量，跨区主路和主要出口净宽不低于 128 px，桥面不低于 96 px，支路不低于 64 px；保证多名居民会合时不形成单点堵塞。
- 共用遮挡：一至两层主体建筑优先放在画面北侧／后景；南侧／前景只放低矮围栏、花草和可穿越的小型设施，禁止高建筑或大树遮挡主路与区域出口。
- 场景母稿直接承担最终地图主体画面；游戏层仅补充碰撞、遮挡、交互、动态、光照和环境音。

## 运行时还原方案

每张地图使用一张封版母稿作为基础纹理，并以同一像素坐标系配置以下语义层：

1. `base`：完整静态母稿；仅在固定内容将被真实动画替代时制作局部无动态修复版。
2. `walkable`：允许角色脚底碰撞体进入的多边形区域。
3. `colliders`：建筑、树干、水域和边界等不可穿越区域；角色以脚底点或小型胶囊体判定，不用整张人物矩形碰撞。
4. `occluders`：从母稿原位切出的树冠、屋檐、拱门等透明图层；每个对象记录 `depth_y`，与角色脚底坐标统一排序。
5. `interactions`：NPC、长椅、喷泉、出口和其他可交互对象的位置、触发范围及朝向。
6. `effects`：水流、草木、云影、灯光和环境生命的贴图、蒙版、路径与节奏配置。
7. `audio`：风、水、鸟鸣和区域生活声的范围、衰减和昼夜状态。

地图按区域懒加载，只常驻当前地图；玩家接近出口时预载目标地图，完成切换后释放非相邻资源。母稿与像素图层保持最近邻采样并限制镜头缩放，避免模糊和亚像素抖动。多人角色共享同一地图本地坐标，网络状态与视觉底图分离。

区域切换统一复用 `PikoMapTransition`：深森林色半透明模糊层覆盖整个世界页面与地图加载过程，目标地图 ready 后显示对应地图名与氛围短句素材，短暂停留后让标题和过渡层柔和退出；加载失败时立即移除遮罩以展示错误反馈。标题在桌面端最多占视口宽度约 42%，不压过地图本身。十五张标题与地图 ID 的关系集中维护在 `piko-map-transitions.ts`，后续切图只切换地图 ID，不复制过渡时序。减少动态偏好下取消缩放、淡入淡出与背景模糊，只保留短暂的静态区域提示。

动态效果遵循局部、低密度和错峰原则。不得直接扭曲整张母稿；已经烘焙在底图中的飞鸟、鲸、强光晕或连续水流若要真实运动，必须先通过局部修复底图或静态覆盖片去重。运行时提供减少动态效果选项，关闭后仍保持完整静态景观。

## 前端渲染底座

- Piko World 使用 PixiJS 8 作为二维地图渲染底座；首版以 WebGL 为稳定基线，WebGPU 只作为后续可验证的增强路径，不作为上线前置条件。
- React 与 TanStack Router 继续负责页面外壳、路由、面板、对话框和无障碍 DOM；PixiJS 实例以独立画布挂载，只负责地图、角色、遮挡、动态效果和逐帧更新。
- 不使用 React 状态驱动角色逐帧移动；输入、镜头、深度排序和动画循环保留在地图运行时内部，只将低频业务状态同步给 React。
- 首版不引入完整物理引擎。行走区、多边形碰撞、出口触发和交互范围使用轻量二维几何规则实现，数据结构保持与 PixiJS 解耦，以便独立测试和后续替换渲染器。
- 交互名称、提示、设置和错误反馈使用 DOM 覆盖层承载；Canvas 只绘制世界画面，不能成为关键文本或无障碍操作的唯一载体。
- Phaser 不作为首版底座：当前不需要地块地图、内置物理和完整游戏场景框架。PlayCanvas 继续服务现有三维查看器，不扩展到 Piko 二维世界。Konva 继续用于标注编辑，不承担持续游戏渲染。
- 首版入口只常驻项目管理中心，默认悬浮在右下角并允许用户拖动，以标准产品 UI 进入独立的 `/piko-world` 路由；进入虾画、虾集等具体项目页面后不显示，避免干扰创作。小镇风格动画入口推迟到世界主体体验稳定后单独设计。
- `/piko-world` 是脱离工作台 Header、任务栏和其他项目组件的全视口沉浸式页面。地图置于严格 `16:9` 的圆角画框内，桌面端保留上下 32 px、左右至少 24 px 的安全间距；画框随视口等比缩小并居中，完整画面不得裁切、拉伸或出现内部留黑，不提供地图拖动和缩放。角色和交互坐标仍使用 `2048×1152` 地图本地坐标。
- 页面画框外使用柔焦林荫环境背景替代纯黑留白：中央保持低对比和低细节，草木与光线集中在视口边缘，并覆盖轻量暗色层，确保地图始终处于最高视觉层级。地图本身只保留圆角裁切，不叠加边框或投影。白天、黄昏、夜晚三态各自使用独立构图，并统一遵守中央低细节安全区与 `cover` 裁切规则；当前默认接入白天状态，黄昏与夜晚素材先作为后续昼夜系统输入保留。
- 世界页面不使用会压缩地图的常驻双栏。返回与聊天按钮以 20 px 间距并排固定在地图画框左上角内侧 16 px；聊天按需从左上角按钮组下方轻微展开为覆盖地图的非模态悬浮面板，不推动或缩放地图。聊天按钮右上角使用暖金底、棕色描边的未读角标，数量只从非本人消息的 `unread` 状态派生，超过 99 条显示 `99+`，打开面板后将未读的非本人消息统一标记已读；该结构可直接承接后续实时消息。聊天框在上一版基础上整体左移 5 px、上移 5 px；桌面端宽度上限 352 px，小屏使用地图内左右各 16 px 的可用宽度。再次点击聊天按钮、点击框体右上外侧的主题关闭按钮或按 `Esc` 均可收起。聊天框与后续 Piko 弹窗统一保持挂载，通过 `opacity`、`translate` 与轻微 `scale` 切换显隐，使用 `--duration-slow` 320 ms 和 `--ease-out-quint`，并在减少动态偏好下关闭过渡。聊天主框使用同宽 RGBA 三段素材：头部与底部按原始宽高比固定，中段只沿纵向伸缩，因此视口高度变化不会压扁头尾装饰，也不会横向拉坏两侧边框；中央暖色承载面直接来自三段皮肤，不再叠加深色磨砂底。皮肤整体使用跟随 Alpha 轮廓的 50% 黑色柔和投影与地图拉开层级。输入框左右各保留 52 px、由上提 10 px 调整为上提 5 px，使用 10 px 圆角、无阴影半透明暖色底与呼应木质框架的轻量棕色边框。消息区左右各保留 52 px 安全留白，气泡使用 8 px 圆角、6 px 纵向内边距与 16 px 行高；消息数组为空时展示正式空状态，接入真实聊天数据后继续作为无历史消息时的兜底。输入框为本地受控草稿：`Enter` 发送本地消息并清空，`Shift+Enter` 换行，输入法组合阶段不会误发；除 `Esc` 外的按键不会冒泡到后续角色移动逻辑。实时聊天接入前，消息区保留三条不持久化 mock 数据，新增消息同样仅存在当前页面，不执行持久化或伪造服务端聊天。文字、焦点、状态与交互均不烘焙进素材。返回固定跳转项目管理中心。

- 地图画框右上角内侧 16 px 放置与返回、聊天按钮同规格的居民设置按钮。打开后先收起聊天，再以同一 320 ms 淡入与轻微缩放显示模态弹窗；背景遮罩、焦点锁定、`Esc` 关闭和关闭后焦点恢复由 DOM 对话框承担。弹窗采用同宽 RGBA 顶部、中段、底部三片拼接，头尾保持原始比例，中段只纵向伸缩；十名已有居民按 5×2 网格展示，支持点击及方向键选择。弹窗内选中项属于草稿，只有点击“选好了”才写入 `dramaclaw.piko-world.resident-id.v1`，关闭未确认的弹窗不会覆盖上次选择；角色运行时接入后直接消费该选择值。

初遇庭院运行包位于 `frontend/public/piko/world/maps/welcome-courtyard/`。`manifest.json` 只声明地图尺寸、基础纹理和数据文件；`data/navigation.json`、`data/occlusion.json`、`data/interactions.json` 与 `data/environment.json` 分别承载导航、遮挡、交互和环境配置。所有坐标统一使用母稿左上角为 `(0,0)` 的地图像素，不存储视口或屏幕坐标。运行时以 `frontend/src/features/piko-world/runtime/map-package-schema.ts` 为唯一校验契约。导航文件已有首轮草案（3 个行走区、13 个碰撞区、3 个出生点与 4 个出口），目前只通过数据契约和几何单测，尚未接入角色运行时或完成实机标注验收；遮挡、交互和环境效果仍为空。

当前停在生产顺序第 7 步的“初遇庭院可运行切片”。已完成 PixiJS 底座、基础底图加载、完整视口适配、独立世界路由、项目中心入口、聊天界面与居民选择弹窗；尚未完成角色、行走碰撞运行时、遮挡、交互、动态、光照与环境音。下一验收门不是继续制作界面，而是把导航草案以开发调试层叠加到地图上，逐区核对行走边界、碰撞体、出生点与出口；调试层确认后再接入首名居民的移动和脚底碰撞。

## 初遇庭院切片边界

- 底图：保留 B01 完整母稿；仅处理喷泉水流、灯光等需要与动态层去重的局部区域。
- 空间：标注可行走区、碰撞区、四向出口、出生点和多人停留区。
- 遮挡：切出大厅屋檐、欢迎拱门、主要树冠和其他允许角色经过其后的前景元素，并记录深度基线。
- 动态：喷泉水流、水面扰动、局部草木、云影和灯光独立配置，不重制完整建筑或植被素材族。
- 角色：从现有十名居民中选择一个预设制作四方向静态、待机和行走；固定 Piko 镇长只制作 SOUTH 待机循环。
- 氛围：先实现水面、喷泉、草木轻摆、灯光和风水环境声；这些效果通过后再判断动物密度。

切片通过条件：主要视角与母稿观感一致；角色不能穿越边界或卡入狭缝；大厅、树冠和拱门前后关系正确；画面无切片接缝、重影、模糊或明显重复动画；地图切换无空白闪屏；减少动态效果后仍可完整使用。

## 环境生命边界

- 远景小鸟、鱼影、昆虫和落叶属于无碰撞环境层，以少量循环或程序化运动提供生命感。
- 鲸歌天港的天空鲸保持远景视差动画，不制作成近景可交互 NPC。
- 小羊、小牛等地面动物需要明确对应区域、行为和交互价值后再制作；当前没有牧场区域，不进入首版资产队列。
- 气球只作为节日或活动变体，不作为小镇常驻装饰，避免把自然社交空间推向游乐园气质。
- 新增 NPC 前先确定职责、停留位置、对话和行为；首个切片只使用一名居民与固定 Piko 镇长。
