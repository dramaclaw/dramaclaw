# 官方 Piko NPC 像素生产规范

状态：v0.6，Piko 镇长昼夜形象已确定，人类居民视觉体系重新设计。

## 目标与依据

- 用于 Piko Piko 低俯角斜俯视 2D 世界的官方 Piko 角色。
- Piko 是小镇镇长／引导者等核心 NPC，不作为平台用户的默认身体。
- 平台用户使用独立的人类居民骨架；两类角色只共享像素密度、光影和世界调色逻辑，不共享轮廓或动画骨架。
- 官方原始形象：`/Users/yangzhen/Desktop/piko形象.png`，作为镇长角色重塑的强结构原型，不只用于配色或符号参考。
- 历史母版：`/Users/yangzhen/Desktop/Piko Piko默认角色母版.png`，不再作为镇长身体结构或轮廓约束。
- 当前比例基线：正式像素稿中人类居民目标高度 56 px、Piko 目标高度 48 px，共同脚底基线 `y=57`；不再依赖已删除的历史比例图。

## Piko 识别边界与创作自由

- 必须保留：原型的非对称阶梯轮廓基因——左向横展的平顶、中央窄颈、下方宽阔阶梯身体、右上侧叶片、低位竖长眼睛、块状手脚；同时保留暖白身体、深靛色高光眼睛和亲和气质。
- 可以优化：轮廓转折、局部比例、叶片动态、五官细节、身体重心和镇长身份表达；整体形态变化控制在原型的 20%–30%，并将纵向比例拉长到适合穿着完整服装，不得重构为另一物种。
- 镇长身份由重塑后的本体、贴身服装、装饰和手持道具共同表达；服装必须按 Piko 的窄颈、阶梯肩、宽身体和短手脚重新裁剪，不能把人类服装直接套用或用环绕式饰件代替。
- 最终形象必须像原型 Piko 在 Piko 世界中的角色化升级，而不是旧母版简单换装，也不是梨形植物精灵、婴儿、宠物、蔬菜、通用幽灵或毛绒玩具。

## 基础规格

| 项目 | 规范 |
| --- | --- |
| 单帧画布 | 64×64 px |
| 输出格式 | RGBA PNG，透明背景 |
| 方向顺序 | SOUTH、WEST、EAST、NORTH |
| 角色轴心 | 底部中心 `(32, 57)` |
| 脚底基线 | `y = 57`，所有方向一致 |
| 概念阶段尺寸 | 独立生成，不与人类同图，不锁定像素高度 |
| 概念体型 | 总高度约为最大身体宽度的 1.25–1.35 倍，禁止接近 1:1 的矮胖比例 |
| 顶部窄颈 | 纵向窄段约占不含叶片角色总高的 18%–22%；不得通过拉长顶部制造整体高度 |
| 游戏内目标比例 | Piko 约为人类居民高度的 85%，在最终精灵重建／缩放阶段控制 |
| 最大目标宽度 | 概念选定后确定，必须完整落入 64×64 px 单帧 |
| 渲染 | 整数倍缩放、Nearest Neighbor、禁止抗锯齿与亚像素定位 |
| 外轮廓 | 深海军蓝，主体 2 px；局部转折可收至 1 px |

64×64 是生产网格，不代表页面显示尺寸。游戏内建议以 2× 或 3× 整数倍显示。

## 方向造型

- 首个可玩版本中，Piko 镇长固定站在初遇庭院并以 SOUTH 正面承担欢迎和对话，不需要四方向静态稿。
- 只有在后续确认镇长需要转身、巡逻或移动时，才启动以下四方向生产规范。
- `SOUTH`：完整双眼、双脚，用于先锁定新轮廓和身份表达。
- `WEST` / `EAST`：新正面概念确认后再设计严格侧面；左右共享同一体积和基线，叶子遵循固定物理安装点。
- `NORTH`：新正面概念确认后再设计，保留手脚、叶子安装关系和背部体积。
- 四个方向的总高度、身体重心和脚底位置必须一致；变化来自转向，不来自角色缩放。

## 分层

1. `shadow`：独立层，建议 26×8 px，冷灰紫，低透明度；不得烘焙进身体或脚部。
2. `body`：镇长专属重塑后的白色主体、眼睛、手臂和脚，不含叶子、服装与阴影。
3. `accessory_leaf`：标志性绿色叶子，四方向分别出帧；与 `body` 使用完全相同的画布、轴心和帧序。
4. `mayor_outfit`：贴身镇长服装；领口落在窄颈，肩线沿阶梯肩，袖口连接手臂，前襟覆盖躯干，下摆停在脚部上方。禁止悬浮、环绕身体或只覆盖下半身。
5. `mayor_prop`：镇长手持道具；必须与手部明确连接，不得漂浮。动画阶段可独立出帧。

每个动画帧都需要记录叶子挂点。初始静态挂点以实际像素稿为准，写入精灵元数据，禁止用运行时目测偏移。

## 动画基线

- 首版固定 NPC 不制作行走动画。
- 首版镇长制作 SOUTH 待机循环，建议每套昼夜形象 4 帧：基础站立、轻微呼吸／叶片偏移、眨眼、回到基础；夜间提灯亮度变化作为独立道具层处理。
- 待机帧从已验收的像素母帧确定性编辑，不使用生成模型逐帧重画，避免轮廓、服装和挂点漂移。
- 若后续增加移动行为，必须先完成并验收四方向静态帧，再制作对应方向动画。
- 第一版行走采用每方向 4 帧、8 fps 循环；先验证脚步、重心和侧面可读性，再决定是否增加帧数。
- 身体上下起伏最多 1 px；叶子可延迟 1 帧响应，但挂点不能漂移。
- 阴影只允许轻微宽度变化，不跟随身体上下移动。

## 验收条件

- 1× 尺寸下仍能通过白色有机体、绿色生命叶和深靛色高光眼睛辨认 Piko，不依赖旧母版轮廓。
- 所有帧仅使用整数像素，无模糊边缘、半透明描边或颜色噪点。
- 四方向脚底落在同一基线，角色切换方向时不跳动。
- 品红背景完全移除，PNG 必须有真实 Alpha 通道。
- 侧面必须从最终选定的新正面概念推导，不回套历史母版。
- 默认叶子、身体和阴影可独立替换或隐藏。
- 镇长服装必须看得出领口、肩部／袖部、前襟和下摆与本体的穿着关系；禁止围兜、尿不湿、悬浮项链、环形披布、单独腰带或只在下半身横向包裹。
- 道具必须由手部握持，并与镇长职责直接相关；不得用王冠或权杖制造统治者形象。

## 人类居民边界

- 人类居民采用独立模块化骨架：身体、发型、面部、上装、下装、鞋子、配饰。
- 首发采用一套共享动画骨架和十个完整外观预设，其中五个偏男性气质、五个偏女性气质；性别表达来自发型、服装与外轮廓，不建立两套不兼容骨架。
- 造型应清楚表达“正常人类”，允许轻度 Q 版，但不得复用 Piko 的白色团子轮廓；通过非对称剪裁、鲜明发型、小镇原生材质与克制的自然／灯光符号形成 Piko 世界识别。
- 拒绝此前的通用黑发、蓝上衣、卡其裤形象；该方案比例可读但过于普通，缺少角色性格、轮廓记忆点和 Piko 世界归属感。
- 十个预设共享相同身高、头身比例、肩宽、手脚位置与待机姿势，以保证后续四方向和动画可复用。
- 男性预设不得重复使用同一种蓬松短发；五名男性必须分别拥有可在纯黑剪影下区分的发型，并各自配置一个克制的头部／上半身识别符号。
- 男性气质不能只靠发型处理：在不改变动画锚点的前提下，使用略宽且平直的脸部、较低重心的眉眼、清楚的颈肩连接、直线型肩部与不收腰的外套剪裁；禁止直接复用女性组的窄脸、大眼、柔肩和收腰轮廓。
- 首发预设不持有手部道具，避免限制移动和交互；个性通过发型、衣装、包袋、徽记与局部配饰表达。
- 默认眼睛采用紧凑深色矩形，每只眼睛左上角保留一个同尺寸高光像素；禁止放大成带大片眼白的动漫眼。
- 正面静态比例以人类 56 px、Piko 48 px 为基线，整数像素实际比例 85.7%，共同脚底基线为 `y = 57`。
- 当前只验证正面静态比例；新 Piko 镇长概念确认前，不制作四方向、换装部件或动画。

## 首个验证门槛

先以已确认的十人正面探索表锁定共享骨架、Piko 世界视觉语言和文化服装体系；十个预设不再分别重生，而是直接从该表拆分、去背景并统一对齐，避免身份、服饰和比例漂移。方向与动画在共享骨架实机验证后统一派生。

## 素材协作流程

1. 我每次直接提供一个素材的生图提示词；角色概念允许在同一张图中生成多个设计用于选择。
2. 用户先判断提示词，再负责外部生成与抠图；未确认素材不放入项目。
3. 用户回传后共同优化；单个素材确认后立即进入下一个素材。
4. 素材全部确定后，由我完成命名、技术检查和项目入库。
