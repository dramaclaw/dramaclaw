# Piko 单条聊天翻译

公聊与私聊共享按需翻译入口。原文保留，译文只在阅读者界面展开，不写回聊天消息，不计入未读或发送回复。悬停和键盘聚焦显示操作，触屏常显；点击翻译后可收起、重试。目标语言默认跟随界面语言（中文或英文），通过入口旁菜单修改；只在本机按账号保存语言偏好。

`POST /api/v1/piko/chat/translate` 接受 `text`（1–80字符，非空白）、`target_language`（zh/en）、`conversation`（缓存命名空间）。需要现有登录认证，并在模型调用前经过可信出网身份准入。使用已配置的 `FREEZONE_TRANSLATION_MODEL` 与现有模型网关能力 `freezone.text.generate`，但使用独立的口语聊天翻译提示，不走创作提示词翻译任务。只提交被点击的一条原文，不附带会话历史。无需增加新的供应商密钥。

当前公聊和私聊仍是浏览器本地演示；conversation 是缓存隔离标识，并非服务器会话权限凭据。接口仅翻译调用者提交的文本，不提供聊天消息查询。真实多人聊天上线时，应改成服务器消息ID，先验证会话成员/消息可见性，再读取原文翻译。

缓存不落盘：前端最多128项，后端每进程最多512项，5分钟有效；后端按用户、会话、原文、目标语言隔离，并合并在途相同请求。失败不缓存。后端每用户每进程每分钟20个未命中请求，单进程最多8个并发模型请求，15秒超时。多worker/多实例上线前应迁移到共享限流与缓存存储，当前额度会随worker数量增长。接口返回429、504、502对应限流、超时、翻译不可用，不返回供应商异常或私聊原文。

测试使用替代翻译器，不调用付费模型；真实译文质量、供应商响应时间及账单需在配置好的环境中另行验收。部署时需要同时更新后端与前端；仅更新前端不会让旧后端出现新接口。
