# 镜头承接（独立开场／自动承接）

在故事片段右侧的「制作备注」下，使用「镜头承接」切换「独立开场／自动承接」。多个上游汇合时，开启自动承接后选择「承接来源」；故事起点没有前置镜头，自动承接不可用。

也可以在虾画里对虾导说：“把这些连续镜头设为自动承接，分支共用上一镜尾帧；换场的镜头独立开场。”

虾导通过视频节点可编辑字段将 `continuityMode` 设为 `auto`。生成下游镜头时，客户端自动读取当前上游视频，复用或截取尾帧，连接图片参考，并在提示词开头用实际 `@图片N` 编号明确要求“首帧从这张尾帧截图开始”；该段以内部标记 `[FMV自动承接]` 包裹，对应界面词条「自动承接」。全能参考或图片参考模式还会列出已连入的人物、物品等图片及其用途；未连入的素材不会被写成已引用。手动生成和虾导运行节点使用同一逻辑。

- 同一源视频版本、截帧位置只产生一张派生图片；并发分支共享同一次截图和上传。
- 手动截取首帧／尾帧也复用同版本已有截图；“当前帧”截图保持原有行为。
- 上游更换视频后，下次生成下游会提取新尾帧，替换该下游的自动承接连线。已有成片不会被自动重新生成。
- 设为 `independent`（独立开场）时，会立即移除该镜头的自动承接连线和自动提示词段，保留手动参考；已截取的尾帧图片节点不删除。
- 多个上游汇合时必须指定 `continuitySourceNodeId` 或独立开场，不按连线顺序猜测来源。
- 故事起点不承接回放边。其它循环承接会被工作流依赖检查阻止，应将切入点设为独立开场。
- 一次工作流中提交多个连续镜头时按依赖顺序执行。单独生成下游且上游尚未完成时会明确报错，不会擅自生成上游或新增后台任务。

尾帧连线带有 `keyframeSlot: first`。使用首帧模式时它作为首帧输入；多图参考模式下仍然是开场参考，无法保证生成画面严格等于输入帧。系统不擅自切换模型或生成模式；素材超过模型限制时停止提交。

自动承接不会创建或挑选人物、物品参考图。需要同时使用这些素材时，先把真实图片节点连到目标视频；可给图片设置“人物”或“物品”关键元素分类，使提示词明确其用途。故事片段的素材参考线始终显示：未选中目标片段时以减弱样式呈现，选中后点亮，避免参考关系“突然消失”。

旧故事不会只因有选项线就自动改变生产关系，需要明确开启自动承接。普通工作流原有视频依赖线继续自动准备尾帧。
