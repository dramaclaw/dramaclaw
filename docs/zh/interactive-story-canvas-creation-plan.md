## 1. 要解决的问题

1. 故事背景、情节和分支虽已保存在画布 JSON 中，但缺少面向创作者的完整剧本入口；目前需要逐个查看节点才能理解全貌。
2. 创作前缺少明确的偏好确认。画风、互动程度、作品规模、主题及改编保留项可能由 Agent 自行推断，用户难以预期产物。
3. 大纲主要停留在对话里。刷新或切换工作区后，用户不能在画布上稳定地看到待确认方案。
4. 创作流水线缺少可见的阶段和当前进度。用户不知道下一步是确认大纲、完善剧本，还是制作视频。
5. 互动广告通常是短内容，不能直接套用影游默认的约七片段、两个选择点和两个结局。

**目标体验**：用户提出创意 → 回答少量关键问题 → 在画布审阅大纲 → 确认后生成可读剧本及剧情树 → 沿着明确阶段制作与验收。每一步均可看到当前结果与下一步，不把“方案已确定”“剧本已保存”“视频已完成”混为一谈。

## 2. 实施原则与现有边界

- 复用现有澄清卡片、`StoryDraftV2`、story tools、画布保存机制和剧情树，不新建平行的剧本数据库。
- 画布仍是故事的持久化事实源。正式故事的标题、梗概、角色、片段、选择分别来自故事组、视频节点和选择边；前端只做可读投影。
- **待确认大纲不是正式故事**：`StoryDraftV2` 要求至少一个片段，不能为了显示大纲虚构故事节点。待确认内容单独存为画布级草稿，确认后才调用现有 Create。
- 写入待确认草稿需要明确的业务入口，并沿用画布 revision、冲突检查和历史恢复；不要让 Agent 绕开 story tool 边界直接覆盖画布 JSON。
- 进度由可验证的持久化产物推导，不能仅凭模型回复或工具调用“已接受”标记完成；媒体生成中不等于视频完成。
- 创作确认、故事创建与付费媒体生成是不同授权。确认大纲不自动触发媒体生成。
- 不将导航中的八个名称理解为八套新审批系统。第一轮完成可见导航和真实状态，独立审核/返工留给后续阶段。

## 3. 阶段计划

### 阶段 A：创作偏好确认

**交付**：在创建互动故事前，Agent 使用现有 `freezone_request_user_clarification` 询问缺失且影响方案的偏好；已从用户描述中明确的信息不重复询问。提问集中、可跳过，用户可自由填写。

| 内容类型 | 优先确认 | 默认/边界 |
| --- | --- | --- |
| 互动影游/短剧 | 画风、互动强度、规模或单次游玩时长、主题；改编项目再问必须保留的关系/转折/结局等 | 不要求每项都回答；缺省值在大纲中明示供确认 |
| 互动广告 | 产品与受众、核心卖点、目标时长、希望的用户动作、可选 CTA | 不套用长篇节点和多结局默认值；未经核实的卖点标为待核实 |

- [ ] 已把提问触发条件和缺省处理原则写入互动故事 Skill；仍需补齐稳定的选项文案/默认组合并完成 Agent 行为验收，广告沿用其专门规则。
- [ ] Skill 已指定复用当前澄清卡片并先做文字选项；仍需通过真实会话确认卡片会按条件弹出，截图式画风缩略图继续作为后续增强。
- [x] 回答后输出可审核方案，包含故事/广告核心方向、关键路径和时长估算，再等待确认。
- [x] “只要方案”的请求止于方案，不写画布；进入画布创作的请求继续阶段 B。

**未完成验收**：需要用真实虾导会话覆盖“信息已给全不重复追问”“自由输入”“15 秒互动广告”“只要方案不写画布”四类行为；当前主要由 Skill 规则约束。

**验收**：已有具体偏好的请求不重复追问；普通影游与 15 秒互动广告得到不同的规模建议；用户自由输入能进入方案；未确认方案不创建正式剧情树。

### 阶段 B：大纲落到画布并确认

**交付**：在画布提供“待确认大纲”视图，能看到背景、主角目标、主要情节、互动点/分支、结局方向、预计单条路径时长及待确认事项。用户能确认或要求修改，刷新后内容仍在。

- [x] 定义小型版本化 `pendingStoryOutline` 数据契约，存于当前画布 metadata；至少包含 `kind`（影游/广告）、标题、背景/创意、情节摘要、交互与结局摘要、时长预算、确认状态及更新时间。字段以展示和审核所需为限，不复制完整 `StoryDraftV2`。
- [x] 提供专用保存/更新入口供 Agent 调用，复用现有画布 revision、幂等、写锁、历史与事件记录；冲突时重新读取并提示用户，不静默覆盖画布人工编辑。
- [x] 在画布上提供可打开的方案卡/侧栏；明确显示“待确认”“已确认”“需要修改”，不把对话中的文字当成已保存结果。
- [x] 大纲获批后调用现有 `dramaclaw_create_interactive_story`；创建成功后关联大纲与正式 `story_id`。确认成功会自动向虾导发送继续创建消息；“需要修改”会进入修改反馈动线。
- [x] 确认后再修改故事，走现有 Get/Patch/Validate；大纲以 `linked` 状态保留为确认记录，不作为正式故事的第二事实源。

**已修复回归点**：revision 冲突只刷新最新大纲，不再静默重试确认；短广告不足 60 秒时按秒显示；Create 确认门禁已下沉到 Service 原子写入层，标准 Agent、REST 及其他调用方对 `pending/needs_revision` 状态均无法绕过，损坏的大纲槽按 fail-closed 处理。

**验收**：保存后刷新可恢复；两个客户端同时编辑不会静默丢改动；创建失败可继续修改并重试；成功创建只产生一棵正式剧情树，且不会触发收费生成。

### 阶段 C：画布剧本总览

**交付**：故事组提供“查看剧本”入口，以用户可读的顺序展示故事背景、角色、情节片段、互动选项、分支去向和结局；从总览可定位到对应画布节点。

- [x] 从正式故事组的 `storySynopsis`、`storyCharacters` 与现有片段/选择边生成只读总览；保留原始画布节点作为编辑入口。
- [x] 区分剧情文案、制作说明和视频提示词；总览默认呈现剧情，不把模型提示词当剧本。
- [x] 分支按选择点展开，显示汇合与结局；循环或条件跳转不会误排成单一线性剧情。
- [x] 无正式故事时显示阶段 B 的大纲；部分节点缺文案时标出缺项。
- [x] 总览保持只读，现有画布节点及 story Patch 继续作为编辑入口，避免形成第二事实源。

**验收**：用户不看 JSON 即可说清故事背景、主要情节、每个选择的去向与结局；总览与节点编辑/Agent Patch 后的画布保持一致；刷新后仍一致。

### 阶段 D：可见创作流水线

**交付**：画布显示阶段导航，采用“策划案 → 大纲 → 剧本 → 角色 → 场景 → 分镜 → 视频 → 完成”。视觉参考不设独立阶段，按角色、场景或视频开场的实际需要准备。每个阶段只显示 `待开始 / 进行中 / 已完成 / 不适用` 等可解释状态；点击可打开相应产物或说明下一步。

- [x] 定义纯读取的阶段推导规则，输入为画布草稿、正式故事和已有制作产物；前后端均从画布证据即时推导，不持久化第二套进度状态。
- [x] 现有可靠产物足以证明完成时才点亮。缺少稳定判据的阶段显示“暂无自动判定”，不假装完成。
- [x] 提供当前阶段、高亮、完成与提示状态；导航在窄屏可滚动，不遮挡画布主要操作。
- [x] 广告使用短流程展示：策划案 → 大纲/脚本 → 画面方案 → 视频 → 验收，不强迫补齐影游阶段。
- [x] 创建、Patch、媒体回填和刷新后重新推导状态；只有实际就绪的视频素材计入完成证据。

**初始状态口径（实施前按代码复核）**：

| 阶段 | 可作为完成证据的候选产物 | 注意 |
| --- | --- | --- |
| 策划案 | 已保存且经用户确认的创作方向 | 只聊天、未保存不算 |
| 大纲 | 已确认大纲或正式故事梗概 | 待确认不是已完成 |
| 剧本 | 正式故事存在、片段可读且校验通过 | 占位媒体允许 |
| 角色/场景 | 已存在并可读取的对应制作资料 | 角色名单只是剧本定义，不是角色资产；暂无统一证据时不自动完成，也不越过该阶段高亮视频 |
| 分镜 | 每个片段已有镜头方案、动态时长与独立开场/自动承接策略 | 视觉参考按需归入角色、场景或视频准备，不设独立阶段 |
| 视频 | 所需路线的实际视频素材就绪 | 生成中/任务接受不算 |
| 完成 | 故事可试玩且所需交付项已验证 | 不等同于故事 Validate 通过 |

**验收**：空画布、待确认大纲、已创建占位故事、部分视频生成、视频全部就绪这五种状态有正确区别；广告不展示冗长的影游流程；进度条不显示无依据的百分比。

## 4. 建议交付顺序与阶段门

1. **A 独立上线**：先让创作输入可控，不依赖新数据模型。
2. **B + C 形成核心闭环**：大纲保存、确认、正式剧本总览必须一起验收，解决“JSON 里有，画布上看不到”。
3. **D 在真实产物上接入**：可以先上完整阶段标题，但仅标记有证据的阶段；其余明确为待完善。
4. **E 作为每阶段回归门**：阶段验收通过后再扩展下一阶段，不把端到端测试全部推到最后。

## 5. 暂不纳入第一轮

- 八个阶段各自独立的审批、回退、版本比较与任务状态机。
- 为画风选择生成新的图片素材库；第一轮先用文字选项。
- 把整个正式故事复制进大纲草稿，或将 JSON 原样展示给用户当作剧本界面。
- 自动发布、自动付费生成、未经试玩即宣称“完成”。
- 把短广告强行拆成七片段、多选择、多结局。
