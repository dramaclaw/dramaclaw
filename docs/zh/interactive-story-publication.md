# 互动影游分享发布

> 最近对账：2026-10-12。分享发布、版本管理与游客播放已有实现；真实部署、移动端及完整媒体验收仍待完成。

每个画布最多保留一个互动故事组；已有故事组时不能再创建、导入或粘贴第二个，可编辑现有故事组或使用新画布。普通分组不受限制，删除故事组后可重新创建。保存及历史恢复均校验此限制；已有多个故事组的数据不会自动删除，需要手动整理为一个后再保存。

普通“添加视频”（快捷工具栏、空白处菜单及点击落点）创建独立视频，即使选中故事组或落点位于组框内也不自动入组。只有明确的“添加片段”或从故事片段继续创建下游视频，才加入对应故事组；下游片段沿用剧情选项连线语义。

故事组工具栏的「发布作品」提供发布管理。首次发布填写信息后「检查并准备」，准备完成停留在结果页，由作者点击「预览作品」，先查看与玩家一致的作品首屏，再开始试玩和确认发布。已有作品默认进入发布管理，固定展示当前版本、分享链接和历史记录；「准备新版」只准备内容，不立即上线。待发布任务可继续准备或预览。发布的是准备时保存的画布版本；后续编辑不会改变已准备或已发布内容。必需视频、无效分支、结构性不可达片段、未配置结局等问题阻断发布；缺少视频等制作准备问题仍可作为非阻塞警告。

## 部署

分享链接自动使用当前浏览器页面的协议、域名和端口，拼接 `/play/{publicId}`，无需配置站点地址。

使用 localhost / 127.0.0.1 / ::1 打开时，链接仅供本机访问。给其他人分享时，请从对方可访问的域名打开本站；手机打开链接时也应使用手机可访问的地址。自动生成链接不会自动建立公网隧道，也不代表公网可达性已验证。

发布元数据、剧情快照、准备任务和锁保存在项目 `state_dir/publications`；视频与封面保存在 `<项目 output_dir>/publications/<作品ID>/<版本ID>/media/`。两类目录随项目一起恢复和永久删除，备份必须同时覆盖 state 与 output。使用仓库 files-sync 备份本地媒体时需启用 `BACKUP_SYNC_OUTPUT=1`；若 output 已由 OSS 持久化，应按部署策略配置媒体备份。全局 `${NOVELVIDEO_STATE_DIR}/publications` 仅保留公开作品 ID → 项目 ID 索引和跨目录移动期间使用的锁；`ST_PUBLICATION_DIR` 现在只指定该索引和锁目录，不再指定媒体存储位置。所有 API worker 需访问一致的项目数据及索引目录；state 和索引目录需支持文件锁及原子替换，媒体目录无需保存锁或状态文件。发布准备使用独立的媒体操作锁保护复制，项目状态锁仅用于读取和提交状态。复制复用 `copy_project_file`，优先使用 OSS 服务端复制，失败或源对象未就绪时回退文件系统。媒体仍存放在原项目 output 路径，不改变播放链接和备份布局。

前端服务需要将 `/play/*` 回退到 SPA 入口，并代理 `/api/v1/public-stories/*` 至 API。现有前端 nginx 的 SPA 回退覆盖该路由。网站应通过公网 HTTPS 提供服务；本功能不会创建隧道或修改域名。

## 内容与版本

第一版媒体必须已归档在本项目 output 目录，并使用 `/api/v1/projects/{project}/media/...` 或 `/static/projects/{project}/...` 相对地址。封面支持 PNG/JPEG/WebP，每个版本选择横版 16:9 或竖版 9:16，可调整左右及上下取景位置；编辑缩略图、作者预览与玩家首屏共用相同比例和取景参数，不改变视频播放方向。视频支持 MP4/WebM/MOV（实际播放能力取决于浏览器编码支持）。外部 URL、带凭据的临时链接及跨项目资源需先通过项目上传功能归档。发布复制媒体后使用独立版本资源，避免草稿覆盖或删除导致线上资源失效。

准备任务状态和输入持久化，同一任务通过文件锁防止重复执行。已接收的后台准备任务遇到项目锁或任务锁超时会自动重试，锁释放后继续执行；等待期间项目目录已被永久删除流程移走时，任务退出且不会重建项目目录。API 操作仍在锁超时后返回忙碌错误。新准备任务从接受到执行结束持续持有独立的存活文件锁，包含后台排队和等待其他锁的时间。服务进程退出后，操作系统释放该锁；作者重新打开面板或页面轮询时，将该任务标记为失败并显示“上次准备已中断”，清理未完成媒体和任务文件。用户点击“重试准备”后，按当前保存的画布创建新的准备任务，不自动续跑旧快照，也不影响当前已发布版本。仍持有存活锁的任务不会被其他 API worker 误判为中断。旧开发记录没有存活锁标记，无法可靠判断是否中断，应重新准备。准备时记录媒体文件身份、大小和修改时间等指纹，复制前后均校验；若准备期间被覆盖，则失败并要求重新准备。旧的未完成任务若缺少来源指纹，也需重新准备。准备失败保留原上线版本并清理失败任务媒体；通过再次准备重试。网络响应丢失时复用原请求 ID 和参数，已接收的请求不受后续画布 revision 变化影响；重新打开发布面板可查看已保存的待发布任务。

作者预览使用实际 Ink 编译结果，编译失败时不允许确认发布。发布、回退和上下架通过原子替换一个作品记录生效，该记录同时保存当前版本、已发布版本集合及上下架状态，版本快照不随发布切换改写。本功能尚未正式发布，不支持开发期间的旧格式记录；旧 state 目录中的发布媒体不会自动迁移，已有开发作品需重新准备并发布。

固定链接为 `/play/{随机作品标识}`。游客接口仅返回播放快照和作品信息，无公开作品列表。拥有链接的人可免登录读取内容；下架阻断后续作品、历史版本和媒体 API 请求，不再签发新的 OSS 链接；已经签发的 OSS 链接在有效期内仍可访问，也无法撤回浏览器已经下载的数据。

新版本在首次成功发布时分配正式版本号并记录发布时间，准备、失败和重试不占正式版本号。切换历史版本保留原版本号和发布时间，也保持当前上下架状态；重新上架需单独操作。

存档留在玩家浏览器，按作品和版本隔离。继续游玩使用原版本，重新开始使用当前版本。浏览器存储不可用时仍可游玩，但无法保存进度。已发布历史默认保留按首次发布顺序最近 10 个版本，可通过正整数 `ST_PUBLICATION_RETENTION_LIMIT` 配置；当前上线版本始终额外保留，下架也不会失去保护，回滚不改变首次发布顺序。发布成功或准备完成后执行清理，有未完成准备任务时延后，避免删除任务引用的素材。升级后首次触发清理也会对已有历史应用此上限。被清理版本无法回滚，其专属链接及对应玩家存档无法继续使用；当前作品链接不受影响。待删除记录先持久化，媒体或元数据删除失败时后续清理会重试。版本数量上限不限制单版本大小，也不对跨版本媒体去重，运维仍需关注磁盘空间。未发布草稿在准备任务结束后自动清理：保留最新准备结果与最新可用版本，新检查失败不会删除上一份可用草稿；作品存在未完成任务时暂缓清理，保护其引用的素材。被替代草稿先删除 output 中的媒体，再删除 state 中的版本目录，失败时保留待清理记录以便重试；仅保留请求摘要以阻止旧请求重试重新生成副本。已完成但残留的任务文件、尚未登记到作品索引的孤立任务会在清理时回收，只有存活任务会暂缓清理。失败或中断任务的媒体删除失败时，版本内持久化待清理标记，下次作者查询或草稿清理会重试，不影响已发布版本。其他窗口中已被替代的草稿需重新检查。

## 玩家剧情探索

发布播放页、作者预览和画布娱乐试玩默认提供同一个「剧情探索」面板，不需要作者配置。面板以剧情地图呈现节点解锁与分支选择，探索完成率保留在播放器工具栏。未体验节点显示标题与锁图标，结局节点标注「结局」；选中已体验节点后，直接在节点内通过「重玩」恢复回溯点。重选恢复最近一次进入该节点时的完整 Ink 状态（变量、剧情开关、访问次数与可用选项），并恢复当时的路线。重复进入同一个节点只保留最近一次到达的回溯点。

探索完成率按当前版本从起点结构可达的剧情节点去重计算。视频播放结束（选择节点进入尾帧选择阶段）后解锁；无视频的选择点和结局展示后解锁，自动衔接的占位片段展示完成后解锁。回溯和重新开始保留累计已解锁节点及结局；地图工具栏定位按钮后的清除图标，经玩家确认后清除该版本的存档、解锁与统计，并从起点开始。旧格式兼容存档仍可续玩，但不会从历史统计猜测解锁或补造回溯点，之后体验的片段开始记录新进度。

打开探索面板暂停视频、选择倒计时、选择确认反馈和自动跳转；关闭后继续剩余时间，原本手动暂停的视频保持暂停。全屏入口将视频、选项、热点与探索面板一起置于浏览器全屏，工具栏闲置时自动隐藏，视频保持完整画幅。不支持或拒绝浏览器全屏时使用占满网页视口的沉浸模式。探索数据与回溯点随版本存档保存在本机浏览器，不跨设备同步；浏览器存储不可用时仅保留本次游玩的内存进度。

播放器工具栏的「返回上一个选择点」恢复本次路线最近一次选择前的状态；可以连续返回，循环剧情中同一节点的不同访问分别记录。重新开始清空本次路线的选择历史，但保留累计解锁。已有探索存档缺少选择历史时，只使用与当时访问记录完全匹配的回溯点，不猜测循环节点的早期状态。

已体验的视频重玩时提供「跳过已看片段」：选择节点进入选择阶段，自动衔接节点仍通过正常 Ink 推进执行变量和开关效果，结局片段进入结局页。未体验、加载失败或未读取到视频时长的片段不提供跳过。结局页显示已达成结局数和节点探索率，并提供「探索其他路线」与「返回关键选择点」。

探索面板在桌面和手机上均显示分支连线地图，汇合节点只显示一次，循环通过返回连线表示；支持拖动、缩放、显示全图和定位当前片段。本次路线的节点与实际经过的连线高亮，其他已解锁节点仍可重选，未体验节点显示标题与锁图标，结局节点标注「结局」。选择文案直接标在连线上，节点操作直接显示在选中的节点内，所有操作共用相同存档与回溯逻辑。节点探索率的口径不变，不以图中重复入口或连线数量计数。

## 接口

作者接口位于 `/api/v1/projects/{project}/canvases/{canvas}/stories/{group}/publication`，要求 editor 或更高权限：GET 管理信息、POST `/prepare` 准备、GET `/{publicId}/versions/{version}` 查询与预览、POST `/{publicId}/activate` 发布/下架/回退。Agent token 调用 `/prepare` 或 `/{publicId}/activate` 还必须持有 `projects:lifecycle`，且会话当前项目必须匹配请求项目；默认 Agent token 不含该 scope，调用返回 403。预览媒体通过同一路径下的版本媒体接口鉴权读取。

影游创作接口中的故事创建、故事修改、大纲保存、大纲确认及制作阶段确认要求 editor 或更高权限；Agent token 还必须持有 `projects:write`，且会话当前项目必须匹配请求项目。只有 `tasks:submit`、`projects:lifecycle` 或 `projects:purge` 不能替代创作写权限。浏览器会话继续按项目角色授权。

游客接口为 GET `/api/v1/public-stories/{publicId}`、GET `/versions/{version}` 和 GET `/versions/{version}/media/{asset}`；只允许已发布且作品未下架的版本，媒体先校验作品上下架状态和版本素材清单，再复用项目媒体的 OSS 分发：对象就绪时返回签名 URL 的 302，否则回退到支持 Range 的 FileResponse。媒体 API 响应使用 no-store；签名有效期复用 `OSS_STATIC_PRESIGN_EXPIRES`。作者预览使用同一分发逻辑，但仍要求项目 editor 权限。


同一版本内引用同一源视频（包括主片与选择循环）时只保存一份媒体副本，不同发布版本仍独立归档。
项目归档或移入回收站会下架全部作品，并阻断公开作品、历史版本及媒体 API 访问；归档期间不允许准备或上架。取消归档或恢复项目后仍保持下架，需作者手动上架。取消归档时也会清除旧版本遗留的上架标记；项目删除状态统一读取项目注册表，不另存发布删除状态。恢复项目保留下架状态，需作者手动重新上架。新的准备和发布在文件锁内核验项目状态；删除登记失败时补偿恢复原上架状态。删除仍使用同一发布锁；若获取锁因权限不足或只读挂载失败，且项目发布目录不存在或为空，则直接删除项目登记，避免尚未使用发布功能的项目被发布目录阻断。已有发布数据、锁忙或其他 I/O 错误不会走此退路；项目配置目录仍需可写。永久删除复用项目原有的目录隔离、清理与失败恢复流程，元数据和媒体分别随 state、output 目录移动；永久删除的目录移动与媒体复制共用媒体操作锁，复制未完成时永久删除返回忙碌；作者轮询、归档、移入回收站和恢复只需短暂获取项目状态锁，不必等待整批复制完成。项目目录被永久清除后，后台任务停止写入，且不重建已清除的目录。公开访问每次检查项目注册表，项目已归档、已删除、已清除或不属于当前节点时拒绝访问，即使残留索引也不能继续播放。

## 离线交付与验收

故事组另有「导出离线包」入口，直接按当前画布快照编译，不需要先发布。ZIP 内含播放器、剧情与视频；完整解压后打开根目录 `index.html`，无需服务器或 CDN。不要单独移动 HTML。离线探索与回溯只保留在本次页面会话，刷新后从起点开始；外部 CTA 仍需网络。大包导出受浏览器可用存储/内存限制，下载失败不输出不完整 ZIP。实现边界见 [离线导出说明](../../frontend/src/features/canvas/story/export/README.md)。

2026-10-12 定向回归覆盖发布准备、版本生命周期、公开播放 UI、剧情探索和导出运行时，命令见 [验证记录](interactive-story-canvas-creation-plan.md#2026-10-12-定向回归记录)。仍需真实浏览器/部署验证分享链接、预览到确认发布、历史版本续玩/回滚、上下架、手机横竖屏、有声自动播放、热点，以及离线包解压播放。玩家路径与探索统计保存在本机浏览器，不提供服务端运营汇总或跨设备同步。

预览后点击“确认发布”会直接将新版设为当前版本并上线，分享链接不变；切换历史版本仍保持原上下架状态。发布或切换会触发历史清理时，界面根据已加载的版本列表提示预计删除的版本及链接、存档影响，取消不会执行操作。有准备任务时实际清理延后。列表仅在存在超额版本时轮询，清理完成后停止，不覆盖作者表单编辑。

## 发布并发回归验证

后台准备任务绑定 state/output 目录的文件系统身份，获取媒体操作锁后、打开任务锁以及提交结果前核验身份。复制期间持有独立的媒体操作锁，不占项目状态锁；查询、归档、移入回收站可继续执行，作品不会自动重新上架。

永久删除的目录隔离入口先获取媒体操作锁，再获取项目状态锁；复制未完成时返回 `503 publication_busy`，可稍后重试。等待期间不持有项目状态锁，不阻塞查询。目录成功隔离后，排队旧任务会因目录身份失效而退出；即使按原内容重建同名目录，也不能写入媒体、任务锁或版本状态。此互斥保证针对应用的项目生命周期入口，不覆盖管理员绕过应用直接移动目录的操作。尚未生成 output 的项目仍可管理发布元数据，目录首次出现后再绑定身份。

草稿和失败媒体清理也获取媒体操作锁，实际删除期间不持有项目状态锁。准备完成、发布/切换后以及作者查询发现中断任务后，都使用同一后台清理入口；媒体锁忙时异步等待后重试。复制与删除共用每个 API 进程/事件循环最多 4 个任务的独立额度，其余异步排队，不占普通同步接口和文件响应的线程额度。同步内部调用在准备结束后等待清理锁；调用方若已持有项目状态锁则延后清理，避免锁顺序倒置。

API 启动未接入 `recover_project_publications`，不承诺重启自动续做或启动即清理。重启后由作者查询标记中断并安排后台清理，作者可手动重试准备。

- 暂停不同项目的实际媒体删除，确认普通请求的线程额度仍可用；取消排队准备时，已接受任务仍完成并执行清理。
