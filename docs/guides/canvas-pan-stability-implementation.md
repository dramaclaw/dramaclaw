# 画布拖动稳定性实施方案

日期：2026-09-27。基线：`4c9dee4`，在当前未提交的封面与平移修复之上增量实施。
对应工作线：`canvas-lod-perf`。取证依据：[对照分析](canvas-pan-stability-analysis.md)。

## 1. 目标与证据

用户要求先明确方案再修改，保证既有画布可以继续使用。

| 观察到的差异 | 本轮处理 | 验收条件 |
|---|---|---|
| LibTV 抓手模式让节点和连线不参与鼠标命中；本地节点回调和内部按钮仍可抢事件 | 抓手模式统一交给画布，平移开始清理 hover，过程中禁止 hover 新增入口 | 从节点、图片、文字、连线开始拖动均只移动视口；选择工具仍能编辑、连接和播放 |
| LibTV 从简化节点升级时保留旧缩略图，随后淡出；本地直接替换子树 | 保存已加载的旧预览，只在完整主体图片加载/解码后撤掉覆盖层 | 慢图无空白；换素材不显示旧图；遮罩不影响点击、尺寸、连线桩 |
| 视频完整节点仍请求原始封面，图片已有分档机制 | 视频封面复用现有 320/640/1280 档位 | 平移不换 src；同档缩放不换 src；播放与导出继续用原视频 |
| 上游节点只变位置，下游引用栏也重新计算 | 给内容消费者独立稳定订阅，缓存同一图快照的索引 | 移动上游不更新引用栏；改文本/素材/连接顺序仍立即更新 |

低缩放平移的 DOM、图片 URL、节点尺寸与 zoom 在前次采样中都稳定，故以上修复覆盖已证实的不足，
不能预先声称解决所有低缩放闪烁。前次约 1 秒调度间隔不能作为真实帧率基线。

## 2. 实施边界

本轮三步串行，每步先看差异，再继续下一步：

1. **拖动归属**：`Canvas.tsx`、`index.css`。
   - 使用现有抓手工具状态与平移类，不把每帧位置写进新的 React 状态。
   - 清掉待执行的 hover 定时器；隐藏节点加号；鼠标离开节点时不重新启动 hover。
   - 参考素材拾取模式优先，使用选择工具的点击语义；抓手透传规则只覆盖画布节点/边，不覆盖全屏弹窗和工具栏。
   - 保留上一轮连线 RAF 合并、小地图真实结束保护和视口结束去重。
2. **媒体交接**：`LodShellNode.tsx`、新 `ui/NodePreviewHandoff.tsx`、`CanvasNodeImage.tsx`、`VideoNode.tsx`、`index.css`。
   - 只在 shell → full 时建立短命覆盖层；只捕获已经加载成功的图片，不截图、不复制播放器。
   - 原 shell 的尺寸、object-fit 和媒体身份作为交接快照；覆盖层绝对定位，不参与 React Flow 的几何测量。
   - 等目标主体图片完成解码后淡出，复用现有快速动效 token；减弱动效偏好下直接撤除。
   - 换源、重新降档、卸载立即取消；加载错误或异常等待有有限退出，避免旧图永久遮挡错误界面。
   - 封面分档仅用于显示，原图查看、引用顺序、视频播放源与生成参数保持原协议。
3. **引用订阅**：`application/useUpstreamGraph.ts`，接入 `VideoNode.tsx` / `ImageGenNode.tsx`。
   - 保留原 `useUpstreamNodes` 的完整几何订阅接口，供仍需要位置的消费者使用。
   - 新增明确用于内容的订阅，按 id/type/data 判断变化；上游移动/选择/尺寸测量不唤醒该订阅。
   - 同一 nodes/edges 快照共用索引，连接顺序仍以原 edges 顺序为准；手动 referenceOrder 照常覆盖。
   - 图数据和连线更新仍走原 store，不引入第二份可写业务状态。

新增聚焦测试：`canvas-preview-handoff.test.tsx`、`upstream-reference-subscription.test.tsx`；
补充现有 `canvas-minimap-pan-mount.test.tsx` 的 hover/抓手回归。
文档：本方案、LOD 台账/claims、STATE，以及相关共享文件的 claims 与串行协调记录。

## 3. 本轮保护项

- 节点坐标、宽高、父分组、连线方向、引用编号、提示词和生成参数采用原有数据。
- 保留旧版完整几何订阅，避免把“位置不更新”的快照传给排序、排版等功能。
- 现有封面归属校验保留，生成新视频后不能拿旧视频封面顶替。
- 不同时调整 LOD 阈值、文本排版、节点布局或自动保存协议，便于区分回归来源。
- 不把 `will-change`、全画布合成层或特效全关推广到默认页面；尚无可信收益证据。

## 4. 连线与保存层的后续门槛

LibTV 使用共享 SVG，本地每条边独立 SVG；这是结构差异，尚不是本地闪烁的已证实原因。
这项单独保留开发环境 A/B 调查，默认产品本轮沿用既有连线层。只有取得可信绘制耗时对照，
并验证命中、重连、删除、框选与缩放后，才另立实施步骤。否则不要冒险替换承载交互的节点层。

自动保存目前已有节点对象指纹缓存；需要进一步优化的是拖动节点的 data 重序列化和拼接。
其涉及草稿恢复/离开页面保存，待本轮可见交互验收后单独处理，避免把保存正确性与渲染改造绑在一起。

## 5. 验证与回退

沿用用户已授权的画布对照测试：

1. 精确执行相关 Vitest 文件，包含旧的 LOD、音频、文件拖入、素材替换、图片档位、小地图/连线平移；不运行付费生成。
2. 执行 `tsc -b`、CE 构建、前端 i18n、diff whitespace、agent guard。
3. Chrome 对照实际画布：10% / 22% / 50%，从空白/节点/连线连续往返平移，松手后内容稳定；跨档升级、点击播放、返回选择工具。
4. 记录节点数量、挂卸载、媒体 src、尺寸、zoom 与手势期间的 hover 状态。浏览器若再次阻止自动化，明确标为未完成视觉验收，不把单测通过写成不闪烁。

任何阶段发现影响几何、引用或生成语义，按本轮独立 hunk 回退。禁止整文件 restore，避免丢失
已存在的封面/平移改动。通过测试也不自动提交或推送。

## 7. 本轮实施结果

三步已按上述边界实现。最终 13 个聚焦测试文件 / 136 项通过，类型检查、CE 构建、前端 i18n
和 whitespace 检查通过。构建保留已有大 chunk 提示。原素材/几何订阅的兼容路径继续保留。

Chrome 中约 22.389% / 128 节点，从视频封面起拖并返回后，节点位置、尺寸、媒体地址与 zoom
保持一致；无误选，无新增播放器。50% 下完整主体图片可显示。跨档过程中没有捕获到短暂交接层，
随后又遇到扩展界面阻止自动操作，因此慢图交接、播放回归与持续闪烁仍需完成动态视觉验收。
单测已经覆盖交接的解码、换源、降档、生成态、错误与减弱动效边界，不能替代真实画面检查。
