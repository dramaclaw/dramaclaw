# 逐帧拉片：证据、契约与收敛方案

> 本文保存需求证据和长篇技术方案；实时状态、阻塞与逐次验证只写在
> `docs/agent/tasks/shot-breakdown.md`。本文不包含密钥、签名 URL 或机器绝对路径。

## 一、目标不是报告，而是可复用素材

2026-09-17 对 LibTV 画布 `802b3f40349b458d9af298f0977b5575` 做过一次实测。
输入是一段 11 秒、1280×720 的画布视频，分镜、动态、音乐三个维度全开，消耗
2.5 积分。证据来自任务完成后的 `project/detail` 节点快照，不是根据界面推测。

实测结果是一颗拉片节点、三个分组和七个普通素材节点：

| 维度 | 分组 | 产物 | 普通节点类型 |
|---|---|---|---|
| 分镜 | `分镜组01｜演奏与聆听·建立→特写→反应` | 两个镜头的四张首尾帧 | image |
| 动态 | `动态｜运镜与动作参考` | 两段按镜头切出的 MP4 | video |
| 音乐 | `音乐｜古风民乐参考` | 一条分离出的 BGM | audio |

核心产品结论是：拉片不是再生成一份文字分析，而是把视频反编译成能直接连接和编辑的
普通素材。结构化摘要仍有价值，但不能替代素材产物。

## 二、原始行为证据

### 2.1 分镜先切镜头，再取首尾帧

四张图来自两个 shot，每个 shot 各取 `first_frame.jpg` 和 `last_frame.jpg`。编号按叙事
顺序重新排成 `S01..S04`，不是等间隔抽帧，也不是按后端 shot id 排序。首尾帧恰好可作
图生视频的输入对，所以切点附近的转场帧必须避开。

### 2.2 动态会真正剪成独立视频

源片被按镜头区间重新落盘成普通 MP4 节点。样本中第一段为 `[0,4]`，第二段为
`[5,11.07]`，切点附近约一秒转场被丢弃。它不是模型生成，而是媒体处理产物。

### 2.3 音乐是 stem separation

请求参数是 `mode: bgm_only`，输入指向源视频，输出是独立 BGM。整轨音频包含对白、音效
和配乐，不能冒充配乐参考。可选分离依赖不可用时可以返回整轨，但必须通过结构化 `mode`
和节点名同时告诉用户已经降级。

### 2.4 语义既要可见，也要可编程

实测产品把语义写进普通节点名，例如：

```text
S02｜大特写·固定｜琵琶按弦拨弦·聚焦演奏
M02｜6s·近景转中景｜聆听女子情绪·反应运镜参考
BGM｜11s·琵琶洞箫合奏｜古风民乐·柔和情绪参考
```

这种形态让普通素材无需新增连线类型就能复用，但程序无法稳定消费名字。因此本仓库保留
两层：节点名给人看，`lens_material` 的结构化摘要给程序和提示词消费。

### 2.5 分组有布局和来源语义

实测分组使用两列网格、350×350 单元、36 间距、顶部 66 标题区，并记录来源拉片节点。
本仓库沿用普通 group，不引入新的拉片素材节点类型；只有一个成员时无法成组，连线退回
素材节点本身。

### 2.6 三个维度分批完成

样本提交后，分镜约 +87 秒、动态约 +94 秒、音乐约 +119 秒分别写入。等待最慢的音乐后
一次性显示全部结果会放大失败面，也让用户误以为前两步没有进展。本地契约因此用任务
`metadata.shot_breakdown_groups` 推送累计分组，并按维度 key 幂等落盘。

## 三、本地实现与上游分支的契约审计

审计对象：本地工作树与 `origin/feat/canvas-video-reshoot-breakdown`（远端提交
`be19c5d3`）。两者不是简单的新旧版本，不能整文件覆盖。

| 契约 | 本地 `freezone_shot_breakdown` | 上游 `freezone_video_breakdown` | 收敛决定 |
|---|---|---|---|
| 入口 | 已有视频节点工具条直接启动 | 工具条只创建专用拉片节点，节点内再启动 | 本轮保留直接入口，避免同时出现两套拉片节点 |
| 维度 key | `storyboard/cameraMoves/musicRef` | `storyboard/motion/music` | 后端暂不改名；前后端共用本地常量，后续若开放公共 API 再做版本化兼容 |
| 镜头检测 | ffmpeg scene cut，阈值 0.2 | scene cut，不足时等距抽帧，阈值 0.3 | 保留 0.2 和首尾帧；补真实素材验收，不从模型时间戳反推切点 |
| 分镜语义 | 一镜一首帧送现有逐帧视觉分析，保留结构化摘要 | 多帧统一视觉提示，模型返回分段、光线、音乐等 | 保留确定性摘要；不再叠一层模型总结 |
| 动态 | 每个检测镜头剪片，可全部输出 | 优先选有运动镜头并限制数量/时长 | 第一版保留完整可编辑素材，真实长片验收后再决定上限 |
| 音乐 | demucs 双轨；缺失/失败显式降级整轨，并可返回对白轨 | 截取音频参考片段，不做人声分离 | 保留本地实现，因为 `bgm_only` 是已有实测需求 |
| 产物 | 普通 image/video/audio 节点 + group | 同样是普通素材分组 | 合并原则一致，无需新增拉片素材节点类型 |
| 落盘 | 每维度通过 task metadata 流式推送 | 任务完成后一次性返回 | 保留流式，最终结果再补齐漏掉的事件 |
| 生命周期 | 依赖通用 SSE + HTTP fallback；尚无可恢复 task key | 专用节点刷新时复位；节点中途删除静默收工 | 本轮补“无恢复句柄则复位”和“源节点已删除则不落孤儿节点” |
| 计费 | 路由当前未声明分析计费 | `freezone.video_analyze`，operation=`video_breakdown`；规则缺失时禁用 | 采用共享计费口径，前端按钮展示同一规则；不写死积分数 |
| 队列/出网 | 普通队列；ffmpeg/demucs 本地，视觉分析走 network leaf | ffmpeg 队列；整项作为 network leaf | 沿用细粒度 leaf 分类；把任务放 ffmpeg 队列，视觉调用仍单独审计 |
| 取消 | runner 使用 `_run_cancellable`；demucs 收到取消会 terminate/kill | runner 使用 `_run_cancellable` | 保留；真实长任务需验收取消后的临时文件策略 |
| 权限/路径 | 项目 editor、静态 URL 限定项目目录 | 同类项目上下文与路径收口 | 保留项目上下文检查，不接收任意磁盘路径或远程 URL |

## 四、最终执行方案

1. 先提交纯领域层：镜头区间、首尾帧命名、分组布局、BGM 正常/降级协议和纯前端投影。
2. 再提交后端共享层：schema → 路由 → task → leaf → runner，并补计费与队列契约测试。
3. 最后提交前端共享层：API、SSE 流式落盘、工具条计费、刷新复位和节点删除保护。
4. 每个提交都从暂存区导出干净快照验证，不能让 LibTV/LOD 的其余脏改动混进测试结果。
5. 没有真实 demucs 与模型环境时只把状态推进到“待验收”，不能把模拟测试写成真实验收。

## 五、不可跨越的边界

- 不把反编译结果写进作者意图 `ShotMetadata`。
- 不把 `output/` 里的签名 URL 或服务端绝对路径写进文档或任务结果。
- 不静默把整轨音频命名为 BGM；`audio_mode` 是必返语义。
- 不整文件搬运远端实现；共享热点只能按契约和 hunk 集成。
- 不用第二个总结模型覆盖已有逐帧分析；摘要必须确定、可解释、可回归。

## 六、验收矩阵

| 层 | 自动验证 | 真实验收 |
|---|---|---|
| 领域算法 | 镜头区间、短镜头合并、首尾采样、命名、网格、降级模式单测 | 人工核对主导景别与运镜 |
| 后端契约 | 路由参数、项目路径、队列、计费、leaf 分类、metadata 累计推送 | 带模型跑分镜；有/无 demucs 各跑一次 |
| 前端契约 | snake_case 归一化、流式去重、分组布局、刷新复位、源节点删除保护 | 页面观察三组分批出现、节点名能区分伴奏/原声 |
| 端到端 | 任务完成结果能补齐丢失的 SSE 分组 | 同一 720p 硬切样片跑三维度并检查取消/刷新 |
