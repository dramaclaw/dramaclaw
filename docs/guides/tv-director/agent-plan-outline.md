# Agent Plan 与《入画》大纲对照 · 2026-09-27

## 结论与边界

本轮完成两条 Agent Plan 文本模型的真实请求接入、改编方向检查点到大纲的有界流程，以及一轮同文档排版修正。**尚未达到 LibTV 大纲的文学质量、完整交付结构和全态像素验收，不得将本轮回归通过写成整个 Director 完成。** 本轮没有部署、提交或推送；原常驻服务仍运行同步工作树版本。

模型通道、结构合同、来源保真、文学质量、UI 像素是五项不同验收。两个模型都能返回合法 JSON，不代表其中的世界规则、时间顺序或人物认识正确。

**最新实验路线：用户要求只做本地 Seed ↔ LibTV Seed。** 此前双模型结果作为历史证据保留；不继续调用DeepSeek，不把不同模型横向比较当作产品对齐。新实验允许人工提炼同源概要，两个独立作品使用同一附件、创作要求、讲法、集数和目标时长，从界面同步推进；具体新结果见文末。

## 1. 对照协议

- 唯一来源是用户本轮提供的《聊斋·入画》完整版故事，不替换为原典或网上改写。
- 隔离 LibTV 项目与本地数据库，不覆盖用户已有作品。无视频、图片、音频请求。
- 共同实验设定：单集、600 秒、三幕、闭合结局、古典志怪、克制/诡丽/后怕而回甘；保留原人物、主要事件顺序、老僧叩画脱险和原结尾，不新增爱情、婚姻、亲属、身世、死亡或转世。600 秒只是控制变量，不是用户不可更改的决定，更不是已测时长。
- 原文缺口单独处理：挽髻过程只在结尾回述；巡使触发有逃念/活人两种人物说法；抹除范围有归乡执念/人间记忆两种口径；老僧解释不自动变成被证明的普适机制。
- 所有模型结果仍是提案；没有自动采纳、审计合格、定稿或开始下一集。
- 原稿、完整提示词、响应、usage、截图和失败保存在被忽略的 `output/playwright/director-ruhua-20260927/`。公开文档不携带 Cookie、鉴权头、签名链接、账户标识或原稿全文。

## 2. 模型与实际参数对应

| UI | 冻结的模型 ID | 实测返回模型 |
|---|---|---|
| Seed-Evolving · Volcengine · Agent Plan | `ark::doubao-seed-evolving` | `doubao-seed-evolving` |
| DeepSeek-V4.1-Flash · Volcengine · Agent Plan | `ark::deepseek-v4.1-flash` | `deepseek-v4-1-flash-260910` |

模型选项来自现有 LocalModelCatalog 的已启用、渠道已配置、文本用途且未阻止条目，不另造模型目录。不把同名的 SiliconFlow 模型暗中改为 Ark。无效/禁用模型拒绝编译，不偷偷回退；已明确选择不受全局默认值变化替换。设置页和聊天模型菜单使用相同合同。单独切模型只影响后续请求，不废弃未变的正文、已有审稿和定稿；旧费用批准仍完整绑定原模型与输入。

第一轮两模型均 HTTP 400。额外 64-token 小探针取得具体原因：SDK 将设置转换为 `max_completion_tokens`，与此同时 extra_body 又带 `max_tokens`，上游拒绝同时传二者。修正只作用于 `ark::`，实际 wire 保留一次 `max_tokens`；普通与流式请求均有回归。compiler 最初升2.6.1，严格格式批次升2.6.2；planning现为2.3.3，使旧能力/报价指纹失效。没有重新派发旧 UNKNOWN 操作。

完整大纲实测超过旧4096默认，短暂提高UI默认后，按用户反馈改为后台自动预算：普通/高级UI均移除token输入和旧偏好读取，API兼容旧客户端显式值；新请求按阶段、集数、时长和来源/现稿规模冻结8192/12288/16384保守档位。它不是供应商能力上限，也不会修改用户故事时长或删原文；技术数字仅审计明细可见。明显超出单次能力时调用前拒绝并要求分段计划，**可靠长篇分块/续写尚未实现**。实际浏览器已验证无token选择器。

自动预算实测暴露的失败不是简单“预算不足”：Flash重复非法占位字段直至截断，Seed正常结束但缺字段/多字段。增加安全校验回执（仅路径和类型）、截断/过滤分类；实际请求从json_object改为同宿主schema的json_schema(strict)，宿主仍独立校验。provider的非空正则语义兼容修复保留宿主约束，拒绝系统性单字正文退化。strict请求被HTTP接受不代表模型必然遵循，失败原文仍保留。

来源权限链也已修复：改编中选择方向只确认讲法，不把M03候选的stakes/obstacle等未经确认的剧情断言提升为事实。M07只收到选项讲法/基调及实际回答；完整旧候选仍保存在审计中。此变化保留原创创意种子的旧合同。

## 4. LibTV 实际流程，不推测私有 skill

通过登录后的隔离项目真实上传、选择与生成观察：

1. 上传来源并输入相同约束；`init_work` 携带 brief、mode=adaptation、source_file、total_episodes=1、episode_duration_seconds=600、work_key。
2. `split_source` → `read_source(chapter)`，读入完整来源。
3. `ask_human(questions)`：四个改编方向，选择后进入总集数/时长等分页问题。翻页不等于提交；最后明确提交。
4. `ingest_source` → `cut_chapter(entries,target_total_episodes)`；创建来源/准备文档并按一集组织。
5. `write_artifact(path,content,more)` 分段写大纲，后续 append。不是一口气把人物小传、场景、道具完整设计全买完。
6. 本次最后的 write_artifact 多次缺 path，出现路径校验失败和 circuit_open；模型仍重复调用。随后 `read_artifact_lines`、`patch_artifact` 将正文补齐。
7. 正文可读，但最后携 plan/title 的写入仍失败，服务端结构计划未成功同步；`finish_script_task` 明示当前结果，然后再 `ask_human` 问调整或继续。未点“继续”，避免越过大纲范围。

原站记录包括 HTTP 参数/响应和刷新后的 `message/list` 历史，提取17条工具调用至 `libtv-tool-ledger.json`。首次抓取未覆盖 WebSocket，事后历史重放恢复工具参数/结果；**不宣称有完整原始流帧、原始时间线或私有系统提示词**。失败回包保留，不能只留最后成功正文。出现过会话标题异常扩写，与实际大纲正文不同，不将错误标题当成整篇大纲分析。

原站也存在内容问题：选择顺叙但钩子又插入闪前；个别动作表述偏离原文；将未明确机制称作规则。对齐的是功能与交付体验，不复制这些错误。

## 5. skill 融合与因果分析

沿用 short-drama 三份原始 /plan 参考：opening-rules、rhythm-curve、satisfaction-matrix，原始哈希不变；M03保留题材与阅读输入基础。不是丢弃技能只换模型。

新增 `source-grounding.md` 从已读 adaptation-core/event-coverage 方法归纳应用规则，并标记改编来源，不宣称是 LibTV 私有技能。M03现为2.3.1，M07现为2.3.2；manifest、provenance、schema/参考指纹和 pinned registry同步。M07新增字段完整性与源动作归属规则；2.3.2根据真实修改轮补正文/修改报告分离、非人格化阻力不强填动机、钩子动作与在场状态核对，short-drama原始引用未删除。知识查询没有匹配，未修改全局技能或进化快照。

- 已观察事件、人物陈述、回述结果、缺口分层；不能由结果擅自安排前置动机。
- 只改讲法的方向选项不能变成四个不同故事；问题要能让用户决定真实缺口。

- 当作品为 adaptation 才加载新来源约束；原创消融 harness 同步条件选择引用，不能误注入新参考。

历史双模型样本的具体失败：Seed稿的反转把老妇/女孩写成已经被消磨归意的人，但原文她们仍能陈述思归与囚禁；DeepSeek稿在第一幕段末、第二幕承接先写孟求助，实际行动段又放回搜查后，且归乡执念/全部记忆在其他字段重新合并成确定惩罚。两者都能在“来源说明”写正确限制，却在冗长重复字段中违反它。旧M03还在问题里预设“为藏身导致盘发”。这些旧结果不能冒充§9最新样本；它们证明瓶颈同时包括模型遵循、提问语义和当前冗余交付合同，不能归因于某一个品牌模型。

观察上 Seed 本组的事件顺序保持好于 Flash；Flash 本组用时短。但样本量不足、上游不相同，不作模型总体排名。LibTV展示 Seed-Evolving；其另一个选项并非本地相同的 V4.1-Flash，不能声称同底模公平速度比较。

## 6. 交付结构与操作缺口

LibTV 本次改编大纲实际为五节：概要设计、这次改写怎么处理原文、篇章划分、钩子预设、改写禁区；钩子下含本集看点与关键伏笔回收。概要包括来源、改写口径、诉求、授权改动、原文范围、必须保留、已做改动。篇章内容重在“讲什么/位置/不能丢什么”。

### 9.6 下一个根因修复切片（尚未实现，先过方案门）

不是继续在同一冗长prompt上盲测；从以下接口处理已定位的问题，再用Seed对同样输入复验：

1. **分开内部规划与改编交付**：在`schemas/planning.py`定义有版本的adaptation交付合同，包含来源范围/用户授权/处理说明/篇章映射/钩子/禁区；来源字段由冻结source与人工回答提供，不让模型冒充审计完成。`outline.py::render_outline`按mode投影五节，保留内部short-drama结构及旧文档兼容。`planning.py`和`writing.py::compile_generation`初稿/打磨必须共用合同，不能仅换前端标题。
2. **限制修改范围，消除全量再创作**：为outline修改定义绑定baseVersion/semanticHash的段落patch与独立changeSummary；每个段落稳定标识，宿主验证目标存在、版本一致和授权范围，未触及段落原样保留。禁止把聊天说明塞synopsis；CAS失效时重新预览，不覆盖新正文。旧完整生成路径保留，不把局部patch强制给所有初稿。
3. **消除强制角色化**：不以必填oppositionTactic/cannotRetreat等技法字段要求每篇作品编出反派计划；内部保留不适用和非人格化阻力表达。词语黑名单不足以解决语义问题，须比较来源主体/动作/因果，而非删“引诱”就算通过。
4. **跨段完整核对**：将明确的人名、事件顺序、发言归属、允许钩子和来源未定项绑定为检查清单；确定性结构/ID/次序检查与语义核对分离。检查所有呈现段落，不只synopsis。模型的“无违规”是待验证陈述，发现矛盾保持待审；保留原回包再修方法/合同后真实Seed复验，不做无限自动重购。
5. **逐节打磨UI**：`DirectorDocumentEditor`/`DirectorStudio`接真实段落diff与changeSummary；顶部上一节/下一节/全部接受/全部撤回，节内接受/撤回，聊天说明可定位变更。保存状态必须区分已生成、待接受、已接受草稿、审阅、定稿；刷新恢复同一patch不重发。报价里不要默认展开整份内部schema，真实参数放可展开技术明细，模型/范围/费用仍清晰可核对。
6. **验收**：本轮两平台源稿与真实失败回包作为固定回归样本；先零费用重放、原创/旧稿/中文名/多集/刷新/冲突回归，再本地Seed与原站Seed按相同概要、方向、修改同步实测。结构、内容、交互、同文同态像素四门分别记录，不拿某一门通过替代其余。
