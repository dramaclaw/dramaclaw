# TV Director 道具设计对齐

更新：2026-09-26。此文只描述本轮道具切片，不替代整个TV Director验收。
人物与场景既有改动保留；源站只读核对，没有修改原作、生成媒体或重新购买已有道具稿。

## 1. 实际观察与交付合同

在用户授权的LibTV既有作品中打开道具设计和编辑器，观测到：

- 「道具清单」一级标题、各物件二级标题，五个加粗标签列表；不是表格或JSON字段。
- 同类手机按持有人分开；记录拍摄/回放/持有不等于已发送，电视内文件与现实道具分域。
- 节点仍用共用生成角色图/全能创作工具栏，不能猜成独立的道具工具栏。
- 编辑器有章节/物件目录、文本格式、正文滚动；右侧聊天仍可见。

| 可见元素（原站顺序） | 本方 `PropDocument` 对应 | 行为 |
|---|---|---|
| 物名（二级标题） | `name` | 按叙事顺序保留，不按名字合并不同对象 |
| 类型 | `type` | 输出语言的简短分类；仅观察科技/证据不足以推断封闭枚举 |
| 戏剧作用 | `dramaticFunction` | 具体行动与结果，不用抽象“推动剧情”替代 |
| 使用边界 | `usageBoundary` | 实际能力、持有人、位置/流转/状态、证据覆盖范围与未知项 |
| 首次出场 | `firstEpisodeId` | 宿主稳定集ID，显示为宿主交付标签，不拿source EP02当工作流序号 |
| 关键集次 | `keyEpisodeIds` | 宿主ID、去重且顺序正确，不能早于首次出场 |

`propVersion=1`、对象`id`为内部合同，不显示为额外字段。
`props=[]`要求非空`emptyReason`；有道具则此值为null。空清单说明是本方防虚构策略，未声称源站实测过这一分支。
旧 `id/name/description` 产物保守展示已有描述，不补造五项，不迁移覆盖历史。
JSON重复键、缺字段、跨文档字段、重复ID、未知/逆序集次均拒绝；原回包先留存，无自动重购。

## 2. short-drama 融合和真实接点

应用内M08包从2.3.1升至2.4.0，指纹：
`eeb6cd535f2dc40644190d7510fd855cb536cf28965018f1284ec12b1c43d5a8`。
人物/场景方法没有抛弃；新增 `references/prop-craft.md`，沿用short-drama：

- episode-writing：主体/行动/对象/结果、道具归属和文书流向连续；
- ai-producibility：写清可见变化，不把心理说明当动作；
- adaptation-core：保留核心因果与已确认设定，不用原创桥段偷改事实；
- event-coverage：逐项清点因果物件，不用抽样读取假冒完整来源审计。

来源hash及MIT说明写入provenance/manifest，输入输出schema、fixture、pinned hash同步；没有改全局short-drama。
`documentKind=props`只加载prop-craft与共用可制作性；筹备加载人物/场景/道具三份；reference选择进入冻结指纹。
这属于可观察合同的维护适配，**不是恢复LibTV私有Skill**。

实际链路：

1. 筹备M08和单文档道具共用严格合同与三语确定性投影，避免一条入口仍输出英文JSON。
2. 单文档要求已有正式大纲或来源；读取完整来源、大纲、当前道具以及保存的人物/场景，不隐式重写别的设计稿。
3. 报价冻结 `prop-design/1.0.0`、JSON模式、responseSchema/hash、propRoot、M08版本/hash和真实模型参数；费用确认显示同一份参数。
4. 原始结果保留，合法结果仅创建待审道具稿，显式接受后才变正式版本。
5. 后续M11读取正式道具内容与版本/hash；更新道具使未发送旧授权失效，供应商调用数为0。

ID在单次产物与宿主合同内唯一，并要求模型保留已提供ID；人类Markdown编辑往返没有完整独立实体注册表，不能宣称跨任意改写的对象ID都已自动稳定。

## 3. 布局与操作实测

1920×1080同视口：两站正文x620/y178/宽680px，正文15px/28.0005px；H1为23.25px/31.3875px，H2为19.5px/27.3px，标题600字重；H2上/下距37.05/9.75px，列表x641、左距21px。本轮复用已对齐的共享编辑器，没有为道具另造字号或表格。局部粗体字宽仍有约0.3px字体渲染差异，不能称整页逐像素相等。

已点测：切换道具→编辑→末项目录；未保存切换取消不丢稿；正式保存v1→v2并刷新保留；选区引用带“道具设计·版本2”回创作器；报价取消无运行，再次明确批准→单次模拟生成→五项富文本候选→显式采纳→刷新后v3、待审数0、三个道具共15个字段。采纳前正式版本仍为v2。执行卡已用三语栏目名显示道具设计，原始docKey仍为props，不改变请求语义。

1200×863与390×844本地截图已人工查看：页面scrollWidth分别等于1200/390，无整页横向溢出；390下编辑器x24/y184/宽342px，目录收起、工具栏换行、正文可滚动。模拟供应商只生成一次，API/SQLite/审批/采纳均走实际代码；它验证交互事务，不替代下一节真实模型内容验收。

本机截图和完整模型证据放忽略的 `output/playwright/`，不把源站完整私人剧本或账户内容复制到公开指南。截图：`director-prop-source-editor-1920.png`、`director-prop-local-editor-1920.png`、`director-prop-local-editor-1200.png`、`director-prop-local-editor-390.png`。

仍有明确差异：源站自动保存/聊天覆盖层，本方模态编辑器/显式正式保存/私有草稿安全栏；媒体工具未接通，不伪造可生成。编辑器分集子目录和全应用壳不属于本轮已达一致的证明。1200/390为本方可用性验收，不宣称源站手机视口也已对照。

## 4. 三份真实模型结果（不是只测mock）

全部通过生产quote→grant→dispatch→待审，供应商回报DeepSeek-V4-Flash；每例一次、8192输出token请求上限，无自动重试、未采纳定稿。完整输入/系统方法/冻结参数/原始返回/usage/隔离SQLite在 `output/playwright/director-prop-live-20260926/`，编辑判断另存 `content-review.json`，原回包未修补。

| 样本 | 用量（输入/输出） | 结构 | 内容逐项判断 |
|---|---:|---|---|
| 单集90秒默剧道具交接 | 7,834 / 1,598 | 通过 | 四因果物件齐全、动作顺序正确；把放回桌面概括为“归还”，未经确认，需局部修订 |
| 双集180秒，两部手机 | 8,114 / 762 | 通过 | 两手机持有人、未发送/回放未转交、确认单第二集首次出场正确；额外把视频列成数字证据条目，粒度与原站样本不同 |
| 改编120秒/source EP02 | 8,598 / 1,189 | 通过 | 两幅画/两文件、画中物/实景、未签/未送达主要边界保留；擅自补“锁盒归陈伯保留”，且把画的递送目标措辞挪到信，需局部修订 |

合计24,546输入＋3,549输出＝28,095tokens，15.72/23.55/26.43秒；实际费用unknown，不报免费或账单硬封顶。三份结构成功不等于三份文学事实通过。未做同模型/同输入LibTV配对生成，不声称文学等价或胜率。

这些反例表明：既有“持有≠所有权”的技能规则仍不能可靠防止跨字段概括漂移。后续应做带来源的对象状态/动作原子事实及人工确认，再检查投影；不是继续盲买或加一句禁词就宣称根治。本轮不偷偷接额外审稿收费链。
