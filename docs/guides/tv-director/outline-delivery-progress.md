五节固定顺序：概要设计 → 这次改写怎么处理原文 → 篇章划分 → 钩子预设 → 改写禁区。三幕可以属于同一集，不把篇章数当集数。1、600、5400 秒均按用户值投影；不新增创作上限。

保留 short-drama 的改编边界与事件覆盖原则，但本块不修改方法包、原始参考或全局技能。不适用的反派策略有明确合同，不要求模型为非人格化环境编出蓄意布局。结构门不能证明文字中完全没有此类语义错误。

## 2. 正文、方法与状态的分离

- `craftNotes` 与 AST 分开返回，保留因果链/情绪/制作风险等内部方法信息，不再渲染出额外六节。
- 模型提出的改动只能留在明确标识的“未授权、待确认”提案区域，不能升级成宿主已授权变更。
- 用户时长、集数、结构、来源、已授权变更等由宿主填入，并在索引标为模型局部修改不可触碰的块。
- “接受、保存、定稿”不写死在可编辑正文里。后续必须从实际 receipt/版本状态显示，避免接受后稿内还永久显示“待审”。
- 所有模型文字按普通文本安全投影；标题/段落中的 Markdown 控制符不能插入新节、可执行 HTML、图片或链接。多行内容不塞进单个 `Block.text`。
- `previous` 仅用于候选重建时保持块身份，不是从旧模型 JSON 覆盖已手工编辑正文的许可。正式后续修改仍须 B04/B05 的受限 patch 与单一正文写口。
