## 2. 自动批量计划与请求对应关系

### 2.1 用户操作

1. 保存人物、场景或道具设计稿；从媒体菜单选择对应类型。
2. 面板默认进入批量模式，按保存稿二级标题顺序自动列出全部素材。单素材模式仍保留。
3. 选实际目录提供的模型、比例、尺寸、质量及扩展参数；逐项提示词可编辑。默认提示词包含该素材完整源段和确认画风，不另花一次模型费用编造资产。
4. 点“准备”原子保存计划、每项意图和画布占位节点；此时不提交生成。
5. 核对完整参数、勾选素材并明确确认未知费用；批准集一次冻结。未选中项取消，不偷发全部素材。
6. 已提交项在画布显示任务状态/结果；关闭面板、刷新、恢复会话不生成第二笔任务。可拖动图片节点，坐标带版本保存。
7. 取消只停止未提交项。已接受、进行中或结果未知的请求不会被取消按钮伪装成退款或自动重新购买。

### 2.2 API 与存储

在已有 `/projects/{project}/director/works/{work_id}` 前缀下新增：

| 路径 | 方法 | 合同 |
|---|---|---|
| `/media/batches` | GET | 恢复全部计划、按 ordinal 排序的节点与意图 |
| `/media/batches` | POST | UUID 批次、作品/文档版本、素材类型、模型、比例、尺寸、质量、扩展参数、逐资产提示词 |
| `/media/batches/{batch_id}/approve` | POST | `selected_ids` 与 `acknowledge_unknown_cost=true` |
| `/media/batches/{batch_id}/cancel` | POST | 仅取消 prepared；保留既有回执 |
| `/media/nodes/{node_id}` | PATCH | 有限范围 x/y、版本 CAS；同一丢响应位置允许读回，不覆盖别人的位置 |

新增 `director_media_batches`、`director_media_nodes`，复用单素材 `director_media_intents`。SQLite 计划事务包括全部节点/意图；末项非法也整体回滚，不能留下部分待付费计划。单批限制 100 项，默认三列，图片比例取实际提交参数；后续计划放在现有节点下方。

节点 ID 与意图 ID 相同，由批次 UUID、素材类型及资产 ID 稳定派生。确认重放沿既有单项原子领取和队列，不复制供应商调用。批准参数中的选择顺序不能改变正式设计稿中的素材顺序。

冻结链：

`资产 ID/源段/源文档版本/作品版本 → prompt + model_id + aspect_ratio + image_size + quality + model_params → 目录指纹 → canvas_id/node_id → task_key/job_id → 持久结果 URL`

实际队列还接收既有 `text_to_image` 模式、供应商/API 模型映射及显式空参考列表；完整请求可展开核对。单素材确认禁止绕过未批准批次。相同批次 ID 不同正文/作品/主体返回冲突；不同批准集不能替换首次批准；版本或目录变化必须重新准备，不能静默发送旧参数。

## 3. 全文事实审计与技能融合

### 3.1 不是再追加一句“不要编造”

创作仍走 M11；审计走独立 M12，保留 short-drama 的单集写作与可拍性参考，而非让创作模型的总分直接放行。应用内 `episode-review` 方法包升至 2.2.0，增加包内 `SKILL.md`、全文事实规则及固定指纹；全局 short-drama 未修改。不声称取得 LibTV 私有技能。

关键实现：`episode_facts.py`、`quality.py`、质量 schema、M12 方法/manifest/pin、`QualityReviewDialog.tsx`。事实合同为 `episode-full-evidence/1.1.1`，质量报告/验证器为 2.2.0。1.1.1 收紧集标题：`# 第2集 手机已经归还` 仍含语义，不能作为纯集号跳过；真实模型请求使用的 1.1.0 回包保留，最后这一规则以零费用复核验证。

### 3.2 审查输入、证据与失效

- 冻结当前稿全部非空段落，包括末段；输入还包括来源、brief、锁定约束、保存大纲/人物/关系/场景/道具、修订基线以及从第一集起的全部已写前集，不只给前一集。
- 每段有稳定清单 ID、来源键、起止偏移、原文与 hash；清单进入输入指纹。源稿、先前任何一集或正文变化都会使旧报告不再可用于定稿。
- 每段必须返回一次，重复/漏段/凭空造 ID 都失败。只有宿主识别的纯栏目/集标题/分隔线可作 METADATA；包含地点、时间、内外的场景标题必须审查。
- 原子事实含主体、关系、值、before/after、real/depicted/dialogue/unknown 层次、SUPPORTED/CONTRADICTED/UNKNOWN/CREATIVE、解释与引证。持有不等于所有，放桌上不等于归还，计划/台词/画中内容不当已发生实景。
- 原句引证必须存在于指定输入，occurrence、起止位置及 hash 由宿主核验。仅抄本段主张不能自证 SUPPORTED；要求独立比较证据。非重叠的同段两句允许证明本段自相矛盾，重复/交叠同一句不能作此证明。
- 本集 source/brief/locked 要求必须与正文执行比较。其他集事件可标 OTHER_EPISODE 并解释；不能用它跳过当前正文。未来事件允许带有效事实，修复初次模型实测暴露的宿主误拒。

### 3.3 定稿闸门

- 有有效矛盾即 FAIL，不能被其他高分或缺证段落冲销。
- 无矛盾但漏段/无效引文为 UNAVAILABLE，不允许定稿。
- 格式与证据全部通过只标 REVIEWED；`semanticCompletenessVerified` 始终为 false。
- 全部非结构段仍要求人工填写核对依据。未知年龄/称呼、新增动作、位置和场景层次不能因引用格式过关自动成为确认事实。
- 审计、人工核对、生成、采纳和定稿分开；报告不会改写正文。旧回包保留，旧版报告不能绕过新门。

局限：模型仍可能遗漏段内某一原子事实、把同一词解释成所有权而不是物理持有，人工点确认也不等于客观真相。当前保留 60,000 输入字符的发送前上限，没有截掉前集冒充完整；超过上限拒绝发送，尚未实现跨块证据聚合。大型长篇不能以本次短样本“9/9”宣称已经验收。

## 5. 全页像素验收：运行了，但没有通过

### 5.1 规则与复跑

`tests/director/pixel_compare.py` 接受两张原始整页图。不同尺寸直接 DIMENSION_MISMATCH；相同尺寸计算 RGB 差异，单通道误差大于 16 视为差异像素，全页差异比例必须不超过 1%。不缩放、不遮罩、不模糊、不自动平移。可附区域诊断，但区域通过不能覆写全页失败。输出 `report.json`、同尺寸时的 `difference.png`；失败退出码 1。阈值是本项目回归门，不是肉眼绝对等价证明。

```sh
python -m tests.director.pixel_compare \
  output/playwright/director-source-chat-equal-1920.png \
  output/playwright/director-local-chat-final-welcome-1920.png \
  --output output/playwright/director-pixel-chat-recheck \
  --region chat:1504,424,400,640
```

输出目录必须全新，防止覆盖先前失败证据。单测已验证：相同图通过、9% 差异图失败、无差异小区域不能让失败全页变绿、尺寸不同失败。

| Top8 按钮区域 | 1520.5 / 676.5 / 367 / 160 |

### 5.4 明确剩余差距

- 全页画布并非相同业务内容；需专用两站同内容合成基准，不能覆盖用户真实剧本或删除既有节点求一致。
- LibTV 的题材球包含 canvas 水波/位移动效；当前本地固定图与 CSS 光晕不是同一渲染。顶部账户/项目壳、底部工具栏数量、禁用分享/插件、模型名称和安全审批状态仍不同；不伪造余额或可用功能。
- 需继续按完整页状态矩阵验收：设定器各子层、编辑五栏目、聊天停靠/浮动、选区、批次审批/取消/恢复、审查失败/人工确认、窄屏及 Windows。已有三宽与历史截图不等于全状态通过。
- 本轮局部尺寸对齐有证据，但**不得勾选整页像素完成或整套 LibTV 等价**。

## 7. 下一步验收动作

1. 先建立不会碰用户原稿的两站同内容合成画布与五栏目样本，冻结字体/视口/缩放/面板状态，整页对照；每次新增状态保留前后原图及指标，不通过遮罩或改阈值过门。
