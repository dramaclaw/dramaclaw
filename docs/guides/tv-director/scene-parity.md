# 场景设计：对齐与实测记录

更新：2026-09-26；基线0298aefa，本轮未提交、未部署。此文只代表场景设计切片，
不代表完整TV Director、私有Skill还原或文学事实质量已通过。

## 1. 源站事实与边界

复用本机忽略的登录态，只读打开用户已有[LibTV画布](https://www.liblib.tv/canvas)，
切换“场景设计”并打开编辑器。没有修改原项目、调用源站生成或拷贝凭据。
观测为一个已有作品、六个场景；包含室内、室外以及电视画面里的独立场所。
这是可见产品合同，不是服务端源码/Skill，也不是覆盖所有题材的保证。

源站结构是“场景清单”H1、“场景名”H2、五条带加粗标签的列表。
并非环境图提示词、镜头表、人物情绪描述或英文键值表。顶部仍为通用“生成角色图”菜单。

## 2. 逐项合同和实际代码

| 可见内容 | 机器字段 | 约束与用途 |
|---|---|---|
| 场景名 | locations[].name | 按叙事顺序，独立地点单列，不按名称排序 |
| 类型 | type | interior/exterior/mixed/unknown；zh/en/vi投影；unknown只表达未确认 |
| 戏剧作用 | dramaticFunction | 具体已确认事件为何发生于此，不是泛泛的氛围 |
| 空间对行动的限制 | spatialConstraints | 进出、视线、阻挡、人物/道具可达性；已知时段可在此体现 |
| 可复用动作位置 | reusablePositions | 具体行动点；单次出现不虚构重复到访 |
| 关键集次 | keyEpisodeIds | 宿主稳定ID、去重/顺序校验，展示deliveryLabel，不拿源集号当ID |

`schemas/planning.py`中的Scene/SceneDocument严格禁止额外字段，保留sceneVersion=1；
`scenes.py`负责重复JSON键拒绝、字段/集次校验、安全Markdown和三语投影。
同名但确为不同地点不粗暴合并，实体ID重复拒绝。字段非空不代表事实正确。

接点：

1. 筹备M08：Bible含人物合同及场景合同；`planning.validate_planning`同时校验人物与场景集次。
   `planning_documents`使用相同的场景投影，不再展示id/name/description英文键。
2. 场景单文档：`writing.compile_generation`先要求已保存大纲或来源，装配M08场景方法、
   `scene-design/1.0.0`、JSON模式、SceneDocument schema及sceneRoot（宿主集次/设定/brief）。
   单独返回场景，不接受混入characters/props的回包。
3. 结果保存：`execution_repository`先保留原回包/usage，再解析投影为待审变更。
   不合法输出记PLANNING_OUTPUT_INVALID，不采纳、不自动修复或再次消费。
4. 下游单文档M11：装入正式场景全文，绑定scenes_version/content_hash；
   场景变动后已批准但未发送的写集请求以INPUT_CHANGED_BEFORE_SEND终止，实际费用0。
   这不是宣称完整M10容量规划或全导演链已完成。
5. 历史：无sceneVersion的旧locations保留名称/描述语义，不编造五项、不改数据库历史；
   已保存Markdown打开不重写。无DB迁移和新端点。
6. 参数确认框修复嵌套对象显示为`[object Object]`的问题；报价和执行记录均显示真实JSON，
   客户端ExecutionParameterValue同步允许嵌套JSON，不强制类型转换掩盖接口合同。

## 3. short-drama不是被替换，而是按用途装配

本轮完整阅读short-drama SKILL及episode-writing、ai-producibility、adaptation-core、
event-coverage；场景知识查询没有已验证经验匹配，使用静态方法并保留来源指纹。
skill-creator用于维护应用内派生包，没有修改全局short-drama。

M08包2.3.1，最终manifest SHA256：
`99da154d5c1cb92e9872296f6f26fa0457e399e8319252652406d83de743f757`。
人物文档合同仍为2.2.0，没有删人物方法；原人物字段规则移入character-craft。
内部documentKind决定加载：characters仅人物、scenes仅场景、preparation两者均加载。
选中和跳过的来源均记入binding，inputSchema/方法/来源/hash变化使旧授权失效。

scene-craft使用人物→动作→物件→可见结果、进出与连续性、完整地点覆盖、原作事实优先；
再映射到上述五项，不强制反派、额外集数或分镜参数。经验反例包括“有门≠只有一门”、
“不替开盒≠不准碰盒”、电视内可见空间单列、信中桥头不是实际到访。
这些是写作约束，不是可靠的自动语义验证器。
