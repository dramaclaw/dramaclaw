# 画布与 LibTV 对齐：能力全集、差距与落地方案

首次取证 2026-09-18；2026-09-19 又在登录态真实打开
[用户指定画布](https://www.liblib.tv/canvas?spaceId=8347675&projectId=64c5bb59a1cb4296bece54f7e7d66994)，
逐类选中视频、图片、音频节点，
并实际打开添加节点、素材库、角色库、生成历史、故事板和 Agent 面板。首次样本
`802b3f40349b458d9af298f0977b5575`（`spaceId=8619202`）继续作为源码对照样本。

本文取代「凭界面记忆列清单」的做法：LibTV 侧结论分别来自真实可见交互、线上前端产物里的
常量/逻辑/i18n/接口表；我方结论均对回仓库文件。我们的完整画布架构、数据流和扩展方案见
[`canvas-architecture.md`](canvas-architecture.md)。

## 零、2026-09-19 目标画布实机复核

### 0.1 证据等级

后文所有新增结论按以下等级理解，避免看到按钮名称就脑补完整实现：

| 等级 | 含义 | 可以证明什么 | 不能证明什么 |
|---|---|---|---|
| UI-实操 | 登录态页面中实际点开/选中后可见 | 入口、上下文、面板字段、交互形态 | 后端请求、收费、最终产物质量 |
| JS-逻辑 | 当前线上 chunk 中找到枚举、函数或分支 | 前端约束、状态结构、接口路径 | 服务端当前一定开放、灰度用户一定可用 |
| 文案可见 | 只找到 i18n/标签 | 产品曾准备或可能显示该能力 | 能力已经上线 |
| 我方代码 | 仓库实现与测试可定位 | 本地设计和已覆盖契约 | 未实跑供应商时不能声称最终生成成功 |

本轮浏览器取证只执行了低风险导航、选择和打开面板。产生了两类远端草稿状态：点击一次
“逐帧拉片”后，LibTV **立即新增一个未提交的拉片节点**，节点数由 93 变成 94；进入一次
“创意片头”的片名设计页后，源视频 payload 保存了 0 秒关键帧版本和项目既有片名。两处都没有
点击最终生成按钮，没有创建生成任务或消耗积分。为避免误删用户内容，未在远端执行删除。

### 0.2 工作区与全局入口

| 区域 | 真实界面观察 | 我们的现状 | 判断 |
|---|---|---|---|
| 顶部视图 | `工作流 / 故事板` 双态；发布与分享；打开 Agent | 无限画布 + 大纲/资产/聊天，暂无全局故事板投影视图 | 明确缺口 |
| 左侧工具 | 添加节点、移动、素材库、人像造型室、生成历史、快捷键、教程 | 添加/选择/素材和帮助分散在工作区内 | 功能有交集，信息架构不同 |
| 右侧大纲 | 画布/资产、节点搜索、类型筛选、评级筛选、展示设置 | 有大纲和资产面板，无评级与同级展示设置 | 部分对齐 |
| 添加节点 | 文本、图片、视频、智能剪辑、导演台、逐帧拉片、音频、脚本、素材库 | 19 类节点与技能入口；有 3D 导演世界，但语义未证实等价 | 类型丰富度接近，产品分组有差异 |
| 添加资源 | 上传、从生成历史选择 | 有上传、生成历史和资产使用 | 已覆盖主要路径 |

“导演台”同名不等于同一能力。我们的 `threeDWorldNode` 是可定位的 3D 世界/镜头能力；LibTV
本轮只确认添加菜单入口，没有打开到足以证明状态模型的深度，因此禁止仅凭名字合并两者。

### 0.3 选中不同节点后才出现的工具

这是本轮最重要的修正：这些能力不在首页静态展示，必须选中具体节点才能看到。

| 节点 | LibTV 登录态工具条（从左到右） | 我们的对应能力 | 结论 |
|---|---|---|---|
| 视频 | 高清、片段重拍、逐帧拉片、智能去字幕、音视频分离、主体消除、创意片头、截取帧、下载、全屏 | 高清、片段重拍、智能续写、逐帧拉片、智能去字幕、音视频分离、剪辑、解析、下载、全屏 | 核心编辑大部对齐；缺主体消除、创意片头；双方各有独有入口 |
| 图片 | 人像质感调节、全景、多角度、打光、九宫格、高清、元素编辑、图层分离、标注/编辑、对比、下载、全屏 | 打光、编辑子项、抠图/擦除/扩图/裁剪/高清、多角度、九宫格、旋转镜像、标注等 | 我方整图编辑较全；缺真正的图层文档和人像质感专项 |
| 音频 | 截取、变速、智能切分、自定义切分、下载 | 工具条主要为下载/格式转换；生成和音色能力在其他面板 | 这是最明显、边界也最清楚的短期缺口 |

本轮还确认：`主体消除` 帮助提示对超过 15 秒的视频不支持；这只是当前 UI 约束，落地时必须
由我们自己的模型目录声明限制，不能把 15 秒硬编码成所有供应商的永久规则。

`创意片头` 已完成受控 UI、网络和线上 JS 取证，完整结论见下一节。最终付费生成没有执行，
所以可以实现交互与任务编排，但不能把竞品最终画质或实际扣费额度写成已验证事实。

### 0.3.1 创意片头：完整 UI / JS / 网络取证（2026-09-19）

它不是“给视频自动加一个开场”的单步任务，而是一条有明确中间产物的两阶段工作流：

`源视频选帧 → 片名设计图 → 文字动效视频 →（可选）让动效融入原片 5 秒片段`

| 阶段 | UI-实操事实 | JS / 网络事实 | 仍未验证 |
|---|---|---|---|
| 选帧与命名 | 首屏标题为“从这一刻，开始你的片头”；可在视频时间轴选帧；片名最多 60 字；“进入设计”不扣费 | 客户端在所选秒数抓 PNG、上传为关键帧，并在源视频 payload 的 `opening` 字段保存草稿版本 | 超长、旋转视频与跨域失败时的线上容错 |
| 片名设计 | 可替换参考图；有智能匹配及简约高级、中式书法、文艺手写、热血动漫、赛博科幻、哥特玄幻六种官方风格；自定义风格支持名称 20 字、说明 500 字和单张参考图；界面提示 `30 / 张` | 风格列表由 `POST /api/opening/list` 读取，类型为 `title_design`；提交逻辑使用通用生成任务，输入包含关键帧、片名、风格说明和可选参考图，产物为图片版本 | 最终图片质量、服务端实际模型和实际扣费 |
| 文字动效 | 要求输入图中已有正确片名；有智能匹配及模糊渐入、动态粒子、故障闪现、手写笔画、动画拼合、震击入场六种官方动效；自定义动效同样是 20/500 字限制；普通模式提示 `150 / 个` | 动效列表仍走 `/api/opening/list`，类型为 `motion`；通用生成任务输入片名设计图，输出固定 5 秒视频版本 | 最终视频质量、音轨行为和实际扣费 |
| 融入原片 | 开关默认关闭；打开后必须从原视频选择固定 5 秒区间，可播放预览，界面提示变成 `300 / 个` | 客户端裁出 5 秒源片；动效任务同时携带标题图与源视频片段，并把关键帧相对位置写进提示；源码默认按 30fps 换算 | 供应商是否逐模型支持图+视频参考、真实融合稳定性 |
| 结果编辑 | 未付费生成，未进入真实结果页 | 当前 chunk 存在选择版本、加文字、蒙版、调色、图层分离、下载、发送到画布、失败重试和历史版本分支；本地文字/蒙版编辑会合成新 PNG 版本 | 这些分支在当前账号是否全部开放；图层文档的服务端完整契约 |

网络层确认了三个模板接口：`/api/opening/list`、`/api/opening/update`、
`/api/opening/delete`。模板写入形状是 `uuid? / name / content / referenceImages / type`；当前两类官方
模板各 6 个。它们是线上实现快照，不是公开 API，我方不能调用或复刻官方模板封面、私有 agent id
和 skill id。

草稿不是新图节点，而是嵌在源视频节点 payload 的 `opening` 文档：顶层保存 `title`、`lastView`
和 `versions`；版本区分 `keyframe / design / motion / text / layer` 来源，并保存
`loading / success / failed` 状态、任务指针、媒体地址和尺寸。前端会持久化 pending task、每 2 秒
轮询通用生成进度，并在刷新后恢复结果。这里值得吸收的是“中间产物可恢复”，不值得照搬的是把
整个编辑器历史继续堆进源 `VideoNodeData`。

#### 我方落地方案门

我方采用**显式派生节点链**，不新增一套隐藏在视频 payload 内的私有版本仓：

1. 动作表登记稳定 id `video.creativeIntro`，首次点击的 effect 是 `spawn`，不是 `paid-job`；打开
   选帧/片名/风格预览不应计费。
2. 第一步复用 `captureVideoFrameBlob` 与现有上传链，生成“片头关键帧”图片节点；再创建已填入
   片名与风格提示的 `imageGenNode`，形成 `源视频 → 关键帧 → 片名设计图`。提交仍由既有图片节点
   完成，费用、模型、失败和恢复沿用现有合同。
3. 第二步从片名设计结果创建 `videoNode`，优先使用模型目录允许的 `imageReference` / 图生视频
   模式，固定目标时长 5 秒，形成 `片名设计图 → 片头动效`。不假设某个供应商永远可用。
4. “融入原片”作为能力门控增强：只在源片不少于 5 秒、且所选模型明确支持图片+视频引用时，
   复用现有剪辑管线产出 5 秒片段，再把标题图和片段共同连接到 `allReference` 视频节点。无匹配
   模型时明确禁用，不能静默退化成普通图生视频。
5. 官方样式先实现成可审计的本地提示预设，自定义样式保存到项目资产域；结果文字/蒙版/图层编辑
   另开工作线，不能为了“看起来一步完成”把它塞进 `VideoNode.tsx`。

这样做保留了 LibTV 的两阶段产品语义，但每个中间产物、费用动作和失败点都在画布上可见、可撤销、
可恢复。MVP 验收门应包括：三语文案；选帧刷新可恢复；进入设计不建付费任务；标题图和动效各自
只有一次显式提交；派生边方向正确；不支持图+视频引用的模型不能进入融入模式；失败后源视频保持
不变；动作注册表、节点持久化、刷新恢复和真实浏览器流程都有回归。

### 0.4 逐帧拉片真实交互

选中视频点击“逐帧拉片”后，LibTV 不是打开一次性弹窗，而是立即在图上创建一个派生节点。新节点
显示源视频信息、替换素材入口、模型标识和三个“拆解维度”：`分镜 / 动态 / 音乐`，最后由用户
点击“开始拉片”提交。这与我们的三维度拉片路线一致，也支持我们“可检查派生节点而非原地覆盖”
的架构决定。

差异在于：他们入口点击即写入远端草稿；我们应保证这类空节点可撤销、可安全清理，并且在真正
提交前不计费。拉片的模型产物和音乐分离质量仍需真实供应商环境验证，不能由界面一致推导。

### 0.5 素材、角色与历史

| 面板 | LibTV 可见能力 | 我们的现状 | 建议 |
|---|---|---|---|
| 素材库 | 风格库、特效库，可新增风格/特效节点；打开工具箱 | 有风格节点和项目资产，无对等特效节点/广场 | 先统一成资产类型，不另造孤立商店 |
| 人像造型室 | 我的/官方角色库；性别、年龄、文化区域筛选；搜索、多选、列表/网格、新建角色 | 有角色/身份资产与资产库，但入口和训练状态分散 | 合并到现有资产域，避免第二套角色库 |
| 生成历史 | 全部画布/本画布，图片/视频/音频，评级，时间排序，批量操作，缩略图大小 | 已有媒体 tab、搜索、排序、批量使用/下载/删除 | 补作用域与评级过滤，价值高且风险低 |

### 0.6 故事板和 Agent

切换故事板后，画布变为按媒体类型组织的列式审阅板，而不是另一张自由图；右侧 Agent 面板可
`@` 引用工作流、节点和资源，并可选择模型、Skill 和生成模式。Skill 列表中存在广告复刻、
拉片复刻、审美 TVC、武侠导演等工作流，但它们是平台技能配置，不能据此推断每个步骤的 API。

值得吸收的是交互架构，而不是技能名称：

1. 工作流图继续作为事实源，故事板是可切换的派生视图。
2. Agent 通过明确引用选择上下文，不把整张大画布无差别塞进提示词。
3. Agent 产出应先形成可审阅的图变更计划，再由统一动作层执行和计费。

### 0.7 导入快照与线上漂移

本地 `state/local/liblib_canvas_import_review/freezone/canvases/` 中保存的目标画布导入快照为
revision 44，共 94 个节点、147 条边；节点分布是 3 个音频、57 个图片生成、34 个视频节点。
它保留了来源 URL、本地 URL、原提示词、原模型、引用、导入模型及图连接关系，但没有恢复
`sourceNodeType` / `action` 等全部 LibTV 私有语义。

真实页面在本轮取证开始时是 93 个节点，说明线上图和本地导入快照已经有一节点漂移；点击拉片
后线上才变成 94。节点总数相同不代表内容相同，禁止用“94=94”判断同步完成。刷新导入应按
稳定来源 id 和版本做合并，并保留本地编辑，不能按数组位置或节点总数整图覆盖。

## 零点八、当前差距矩阵与落地次序

| 优先级 | 能力 | 当前差距 | 推荐落法 | 理由 |
|---|---|---|---|---|
| P0 | 统一动作注册表 | 工具条组件内混合可见性、任务和投影 | 先建立 action descriptor / command 层 | 后续每加一个按钮都能少复制一套状态机 |
| P0 | 故事板视图 | 无全局列式审阅 | 先做只读派生投影，再接排序/批准 | 用户价值高；不需要复制图数据 |
| P0 | 音频截取/变速/切分 | 截取、变速、智能静音切分和自定义切点已落地；节拍/语义切分未做 | 统一走动作注册表；切分先预览，确认后串行扇出既有单段任务 | 基础编辑闭环已完成；后续算法增强必须另行取证 |
| P0 基础已实现 | 创意片头 | 选帧、六类片名/动效样式与显式三阶段节点链已落地；原片融合未做 | 保留现有不计费编排；下一步按模型能力接固定 5 秒原片融合 | 基础链已真实刷新验收；最终供应商画质与真实扣费仍需端到端验收 |
| P1 | 视频主体消除 | 缺失 | 派生视频节点；限制来自模型目录 | 复用视频编辑生命周期，不覆盖源片 |
| P1 | 图片图层分离 | 只有整图进出 | 版本化 layer document，支持排序/锁定/合并 | 不能继续往 `ImageGenNodeData` 堆可选字段 |
| P1 | 智能剪辑 + 字幕/文本轨 | 只有手工媒体时间线 | typed tracks + Agent edit plan | 高价值但跨预览、字体、导出，需专项线 |
| P1 | 角色/实体库统一 | 能力分散 | 扩展现有资产域、标签和训练状态 | 避免两套素材事实源 |
| P2 | Script V2 | 固定表格，缺三态视图和资产锚点 | 先定义版本化脚本文档再迁移 UI | 数据模型先于界面 |
| P2 | 历史/评级/展示设置 | 缺部分筛选 | 补作用域、评级和显示偏好 | 低风险体验提升 |
| P2 | 工作流版本/回收站/协作/市场 | 平台能力不完整 | 分别立项，不绑在节点工具改动中 | 成本与本地优先定位差异大 |

截至 2026-09-19，音频 P0 已形成可恢复的最小闭环：智能模式由后端在项目内源文件上执行
`ffprobe` + ffmpeg `silencedetect`，只返回最多 24 段的连续预览；自定义模式在前端解析切点。
两种模式都不在分析阶段写媒体或画布，用户确认后才逐段复用既有 `freezone_audio_transform`
任务。由于项目级 ffmpeg 队列容量为 1，客户端必须等待上一段进入终态后再提交下一段，避免批量
请求稳定触发 429。这里的“智能”明确是可配置静音检测，不等同也不冒充 LibTV 未公开的算法。

不要照搬的部分：积分/模板市场和社区分发、依赖私有云的工作流服务、未验证的 mention 状态机、
以及任何原地覆盖源媒体的快捷做法。我们的 local-first/BYOK、显式主线提交、派生节点可追溯和
失败可恢复是应保留的产品优势。

截至 2026-09-19，创意片头基础链已按上述方案实现：视频工具条打开独立选帧弹窗，确认后只上传
关键帧并创建 `exportImageNode → imageGenNode → videoNode`，不会自动提交图片或视频生成任务。
片名、所选样式、提示词、5 秒时长与来源 id 都随节点保存，刷新后节点和三条边仍在。关键帧使用
`exportImageNode` 而非 `uploadNode` 是必要约束：后者没有 target handle，强行使用会让源视频到
关键帧的边被统一建边规则拒绝。原片 5 秒融合仍未实现，不能把基础链描述成完整对齐。

## 一、取证方法与它的边界

## 四、片段重拍：他们的实现

这是下一步要做的功能，所以把他们的实现逻辑完整记下来（chunk `2l6x857x-mm1x.js`）。

常量与规则：

- `SEGMENT_REMAKE_MAX_RANGES = 5`，`SEGMENT_REMAKE_SOURCE_TOKEN = "{{Mixed 1}}"`
- 源视频必须 ≥ 4 秒（`isSegmentRemakeSourceDurationSupported`）
- 单段时长 4–30 秒，内部以**厘秒整数**运算（`400`–`3000`），出参才 `/100` 回秒
- 段间不得重叠，且靠后段的 start 不得早于前一段的 end
- 末段越界会被截到源时长，截完不足 4 秒则把 start 往前挪，挪不动才判失败
- 拖拽改边界时（`resizeSegmentRange`）最小段长按 **4.1 秒**限制，比提交校验的 4.0 秒多留
  0.1 秒余量——这是防浮点抖动导致「拖到刚好合法却提交失败」
- 新增一段（`insertSegmentRange`）：默认长度取 `min(5, 空隙长度)`，以点击点为中心放置并
  clamp 进该空隙；已有 5 段时直接拒绝

失败语义值得照抄：`prepareSegmentRemakeRangesForSubmission` 只要有任一段不合法，
就返回**空的 ranges + failedRangeIds 列表**，而不是「把能提交的提交掉」。理由很实际——
部分提交会产出一个用户没预期的视频，还得再花一次钱。

最关键的一条设计差异：**他们没有「每段一个意图输入框」**。用户在同一个提示词输入框里写，
每段以 `{{SegmentRange:<id>}}` 内联标记插入，标记之后、下一个标记之前的文字就是那一段的
意图（`buildSegmentRemakeEditSegments` 按标记切分，`syncSegmentRangeTokens` 维护标记与
区间的同步，`expandSegmentRemakePrompt` 在提交前把标记展开成
「将 {{Mixed 1}} 的第 X 秒到第 Y 秒」这样的自然语言）。好处是段与段的先后、衔接关系
用户可以直接写在一段话里；代价是要维护标记与区间的双向同步。

提交结构（`buildSegmentRemakeEditSegments`）：

```json
"editSegments": [
  {"timeRange": {"start": 3.0, "end": 7.0}, "duration": 4.0,
   "prompt": "这一段改成夜景", "videoUrl": "asset://..."}
]
```

和提示词一起发，不是二选一：`prompt` 里带展开后的自然语言，`params.editSegments` 带结构化
那份，`videoUrl` 用 `asset://` 协议引用画布素材。我们 `videoRangePrompt.ts` 的注释写的是
「结构化那份等上游支持了直接生效」——现在可以确认，他们是两份同时发的。

## 五、智能续写：他们的实现

常量（chunk `14-zdlybef4mc.js`）：`VIDEO_CONTINUATION_REFERENCE_MIN_DURATION_SEC = 4`，
`MAX = 30`；初始选区 `{startSec: 0, endSec: min(源时长, 30)}`。

绑定对象存在目标节点上，形状是
`{kind, version: 1, sourceNodeId, sourceToTargetEdgeId, range: {startSec, endSec}}`，
校验靠 `hasDeclaredVideoContinuationEdge`——那条边必须还在，且方向是 source→target。
我们 `ContinuationBinding` 的设计与此同构（我们额外比对了 `sourceVideoUrl`，用来识别
「源节点没删但内容换了」，他们用 `sourceVersion` 达到同一目的）。

提示词分两层：给模型的是 `对 {{Video 1}}进行续写：` + 用户输入；给用户看的是
`对 {sourceLabel} 的 {mm:ss}-{mm:ss} 片段进行续写：`。区间时间在可见层按 `floor(start)` /
`ceil(end)` 取整——给人看的不需要小数。

两条我们之前不知道的实现细节：

1. **续写会真的把选中片段裁出来**，不是只传时间区间。他们的错误文案里有
   「视频片段准备失败」「裁剪视频合规认证失败」「裁剪视频未通过合规认证，请重新选择片段」，
   说明链路是：裁片 → 合规审核 → 作为参考视频提交。
2. **模型门控**：只有 `properties.supportVideoContinuation === true` 且支持 `mixed2video`
   模式的模型才出现续写入口，默认优先选 Seedance 2.5；不满足时提示
   「当前模型或模式不支持智能续写」。

### 第一步：片段重拍

1. `videoRangePrompt.ts` 补齐三件事：厘秒整数运算（消除浮点比较）、
   `insertRange` / `resizeRange` 两个交互函数（边界规则照第四节）、
   失败语义改成「任一段不合法则整体不可提交 + 返回 failedRangeIds」。
   现有的 `validateRemakeRanges` / `buildRemakePrompt` / `buildEditSegments` 保留。
2. 意图输入沿用我们已有的**每段 intent 字段**，不跟进 `{{SegmentRange}}` 内联标记方案。
   理由：标记同步是一套额外状态机，收益只在「跨段连贯描述」这一种写法上，而我们的
   `TimeRange.intent` 结构更容易做区间与文案的一一校验。这是有意分叉，不是遗漏。
3. `VideoNodeData` 加 `remakeRanges?: TimeRange[]` 与 `remakeSourceDurationSec?: number`，
   随画布持久化；源视频换了就清空。
4. 播放条上的区间选择 overlay：参照 `isClipMode` 的浮层实现，复用同一套快捷键口径。
5. 提交走现有 videoEdit 路径，`prompt` 用 `buildRemakePrompt`，同时带 `editSegments`。
6. i18n 三份都要补，文案口径对齐他们（时长限制、空隙不足、留空即原样重跑）。

验收：源片 3.9 秒时入口禁用并给出原因；5 段之外无法再加；把某段拖到与相邻段只剩 4.0 秒
空隙时提交被拒且指出是哪一段；提交后请求体里的提示词与面板上的区间一致。

**已落地（2026-09-18）**，与上面计划有三处有意的分叉，记在这里免得下次又去翻代码：

1. **重拍不在源节点上就地改，而是在下游派生一个「片段重拍」节点**，源视频靠连线带过去
   （`isRemakeNode` / `remakeSourceUrl` / `remakeSourceDurationSec` / `remakeRanges`）。
   和「视频高清」同一个模式。理由：重拍产出的是一条新视频，覆盖掉用户手里那条没道理，
   派生出来还能两条并排比。生成本身仍走 videoEdit，没有新端点。
2. **`editSegments` 暂不发**。`model_params` 会按媒体目录里声明的参数做严格校验，
   目录里没声明的 key 直接被拒——所以结构化那份留在 `buildEditSegments` 里备着，
   等某个模型的目录条目声明了 `editSegments` 再接上去，那时候不用改逻辑层。
   当前真正生效的是提示词那份。
3. **指代源视频用「这段视频」，不用 `@视频1`**。我们后端按编号解析引用，而视频编辑
   模式下源视频是独立字段、根本不进编号引用列表，写个编号只会解析失败。
   LibTV 的 `{{Mixed 1}}` 是他们自己那套 mention 归一，抄不过来。

区间选择条 `VideoRemakePanel` 放在节点**上方**（下方已被生成面板占满），胶片条复用
`compose/filmstrip.ts` 的缓存抽帧。逻辑层 36 条单测全绿。

2. 前置片段要真裁：走我们已有的 `run_freezone_extract_shot_assets` 剪切能力产出片段资产，
   再作为参考视频提交——不要只传时间区间，他们的实现已经证明这条路是必须的。
3. 模型门控：模型目录里加一个 `supportVideoContinuation` 等价标志，不支持时入口置灰并
   说明原因，不要提交后才报错。

验收：选区短于 4 秒或长于 30 秒时确认按钮禁用；源节点删掉后续写节点提示重选而不是提交失败；
生成的节点名带续写标记，能反查源节点与区间。

**已落地（2026-09-18）**，两处决定记下来：

1. **裁出来的前置片段落成画布上可见的节点**，而不是藏进续写节点的字段里。续写效果不对
   时第一件要查的就是「前提这段裁对了没有」，藏起来就查不了；而且它本身也是一段可复用
   的素材。链路是：源视频节点选区 → 复用剪辑（`freezone_video_compose`）真裁一段 →
   落成「续写前置片段」节点 → 再连出一个续写节点，绑定认的是这条边。
2. **模型门控沿用 `video_edit` 能力**，不新造一个 `supportVideoContinuation` 位。目录里
   声明了 video_edit 的模型（当前五个）就开放入口。造一个我们无法验证真假的能力位，只会
   让入口全都灰着，或者灰错。

绑定（`continuationBinding`）存 sourceNodeId / sourceEdgeId / range / sourceVideoUrl，
提交前用 `isContinuationBindingValid` 核一遍：边断了、片段被换成别的视频，都会拦下并要求
重选，而不是拿着一个不存在的前提去生成。

### 第三步：导入器补齐节点类型

`liblibNodeKind()` 至少要认 20 / 21（脚本）、35（智能剪辑）、40（参考）、45（拉片）、
50（剧本），把它们映射到我们已有的节点或至少保留 `liblibAction` 与原始 payload，
让「导入一张完整画布」不再丢语义。这一步独立于前两步，可以并行。

**已落地（2026-09-18）**，做法比按类型号逐个映射更稳：**认不出来的类型改看它带的素材**。
35 / 40 / 45 这些类型我们没有对应节点，但它们身上大多挂着素材（智能剪辑挂剪好的视频、
参考节点挂被参考的图、拉片节点挂产物），于是先读 `_resourceMeta.items[].kind`，读不到再
看地址后缀，有图当图、有视频当视频，实在什么都没有才落 `liblibMediaNode` 素材卡。
另外 10（COMMENT）直接落成文本节点——批注的内容本来就是一段文字。

按类型号硬映射的那条路没走：脚本(20/21)和剧本(50)的 payload 结构我们没有对照过，
映射成 `scriptNode` 只会得到一个空表格，比一张带标题的素材卡更糟。等真正需要时再对结构。

## 六点五、实机联调发现的问题（2026-09-18）

功能写完不等于能用。在本地 dev server 上把画布真点了一遍，逮到四个问题，都已修：

**1. LibTV 导入但没本地化的素材，所有服务端视频操作都会失败。** 控制台里是
`400 url must be a same-origin path: 'https://libtv-res...'`——后端只收同源静态路径，而
「网络素材」节点的 videoUrl 还是 LibTV 的绝对地址。界面上的表现就是「点了逐帧拉片没反应」。
现在这些按钮在这种节点上直接置灰，提示先「一键本地化」，而不是等请求 400 回来。

**2. 节点工具条被挤出视口，按钮点不到。** 实测：工具条宽 746px，可视宽 444px，左右各有
约 150px 在视口外。加到第十个按钮时必然发生。改了两处：片段重拍和智能续写收进一个
「再创作」下拉；工具条本身加 `max-w` + 横向滚动 + 文案不换行，从此不可能有按钮跑到视口外。

**3. 重拍节点的模式会被顶走，圈好的区间被静默忽略。** 保存下来的节点数据里抓到
`genMode: "allReference"`——「上游有视频且模型不支持 video_edit 就切全能参考」那条兜底
把重拍节点也一起切了。于是提交走普通生成分支，用户圈的区间**一个都没进提示词**，还照付
一次钱。现在重拍/续写节点会把模型换成支持视频编辑的那个并钉死模式，一个都换不到时提交
被拦下并说明原因。

**4. 新建的节点落在视口外，看着像「点了没反应」。** 落位是找空地，实测新节点落到源节点
左边 658px，屏幕上什么都没发生。现在创建后把镜头带过去（`requestFocusNode`）。

另外两处顺手改掉的设计问题：重拍选区条原本放在节点上方，那条带是 React Flow 的节点工具条
的地盘——工具条是独立浮层，永远压在上面，选区条会被整条盖住点不到，现在排到生成面板下方；
选区条上的 ✕ 原本会把节点踢出重拍模式且回不去，现在只清空所选片段。

## 六点六、节点工具条：按 LibTV 实测规格对齐（2026-09-18）

在他们画布上选中视频节点，直接量了工具条的计算样式，不是照着截图描：

| | LibTV | 我们（已对齐） |
|---|---|---|
| 动作顺序 | 高清 / 片段重拍 / 逐帧拉片 / 智能去字幕 / 音视频分离 / 主体消除 / 创意片头 | 高清 / 片段重拍 / 智能续写 / 逐帧拉片 / 智能去字幕 / 分离音视频 / 剪辑 / 解析 |
| 条背景 | `rgb(38,38,38)` | 同 |
| 条描边 | `0.5px solid rgb(54,54,54)` | 同 |
| 条圆角 / 内距 / 间距 | 12px / 4px / 4px | 同 |
| 条高 | 41px | 41px |
| 相对节点 | 居中，上方 32px | 居中，上方 32px |
| 按钮高 / 圆角 / 字号 | 32px / 8px / 13px | 同 |

两点判断记下来：**片段重拍在他们那儿是平铺的第二个按钮**，不是藏在下拉里，所以我们也
平铺（此前一度收进「再创作」下拉，已改回）；**智能续写他们不在工具条上**，是在生成
流程里触发的，我们暂时挨着重拍平铺，免得再多一层菜单。他们的工具条同样会超出窄视口
（实测 908px），我们额外加了最大宽度 + 横向滚动，这是有意比他们多做的一步。

## 六点七、端到端实跑（2026-09-18）

在本地 dev server 上把片段重拍从头点到尾，又逮到一个只有真跑才会出现的问题：

**模型的参考视频时长上限会把重拍直接顶掉。** 自动换上的 Wan 3.0 声明
`referenceVideoMaxSeconds: 15`，而源片 15.093 秒，后端回 `400 video reference duration
must be <= 15s`。改了两处：挑模型时把「这条源片放不放得下」一起算进去，并优先选**明确
声明了上限且装得下**的模型；提交前对源视频也跑一遍时长校验（此前只校验音频），
让用户看到的是可读的中文提示而不是后端的英文 400。

还剩一个**不是代码问题**的拦路石：这台机器没配 `OSS_RELAY_AK` / `OSS_RELAY_SK`，
任务能建、能派发，到调用视频生成器那一步报 `OSS media relay config missing`。
配上这两个密钥才能真正出片。

已跑通的部分：工具条 → 片段重拍 → 镜头自动跟到新节点 → 节点本体上出现源片胶片条 →
点一下截出 5.0s 区间并显示时长角标 → 写意图 → 区间与意图随画布保存、刷新后还在 →
模式锁在「视频编辑」、参考列表里挂着源视频 → 提交建出任务。
