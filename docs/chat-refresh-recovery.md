# 聊天刷新后的忙碌状态恢复

执行中刷新会按现有规则取消旧连接的 Agent。若新连接先收到 busy=true，而取消完成通知发给旧连接，页面可能永久停留在思考中。

收到 busy=true 的 scope.changed 且本地仍忙碌时，每两秒重新读取服务端历史。确认结束后恢复空闲，断线、空闲或卸载时停止定时器。不改变断线取消任务的语义。

回归测试覆盖 busy=true → 再次请求 scope.set → busy=false，并确认空闲后停止请求。

2026-11-10 本机完整应用与真实 Agent 复验：隔离项目中发送请求，执行中刷新，刷新后一度显示忙碌，随后自动显示“已取消本轮请求”并恢复输入，全程未点击停止。再发一轮请求，真实画布摘要工具执行成功，回复完成并恢复空闲。该真实验收运行于同时包含 OOM 修复的工作区；独立分支另跑 hook 回归测试验证。
