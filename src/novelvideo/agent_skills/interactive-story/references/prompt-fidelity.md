# 剧情到视频提示词的保真

适用于首次准备、批量改写和修正 `video_prompt`。先读取当前 `script`、`production_notes`、`video_prompt`、真实参考素材和节点参数，以用户最新确认的剧情为准，将其转换成可拍摄镜头描述而不擅自改编。

- 保留关键事件、先后顺序、人物意图和结束状态。“即将看消息”不能改成“已经看完并爆发”；汇合片段不能假定玩家走了某一前置分支。
- 对白、旁白、手机消息、标牌和字幕逐项核对，保留原文及说话人或呈现位置。不能把具体消息缩成“显示消息文字”，也不能用表情替换对白。
- 区分剧情文字和玩家选项。播放器选项不会让剧情字幕或手机文字自动叠加；没有已验证的后期文字能力时，在提示词中保留文字要求并说明精确文字仍需成片核验。用户选择后期处理时，记录原文和位置为待完成项。
- 可以补充景别、光线、运镜和参考用途，但不得增加改变情节的新动作或提前情绪结果，也不要让风格词覆盖剧情要求。
- 使用节点详情 `reference_media` 返回的真实 mention 绑定身份、场景和产品；mention 是工具返回的素材引用标识，不自行编号。身份参考图的姿势或表情不覆盖本段动作。尾帧作为开场时，说明后续动作从该状态自然发展。只有文字元信息时，不声称看清图片内容。
- 检查动作和对白能否装进当前时长。装不下时报告冲突，不静默删台词、增加定格或拆分剧情。仅修提示词时保留模型、时长、画幅和声音参数；提示词写“竖屏”不等于节点参数已改变。

## UI 与收尾

- 不给每段追加“画幅、时长及声音能力以节点实际设置为准”；这是节点核验规则，不是模型可拍摄内容。
- 只在需要停留选择或承接尾帧时要求稳定收尾。普通转场按剧情继续，结局按已确认的剧情和情绪收束。
- 允许用户要求视频内装饰 UI，例如文字气泡或标签。写明外观、位置和时机，不用装饰数值冒充真实统计或玩法结果。
- 视频内按钮本身不可点击；成片后需通过 [interaction-options.md](interaction-options.md) 的热点配置真实点击区域，并核验文字、位置、停留画面和画幅适配。不要根据未生成画面编造坐标，也不要重复叠加同文案的播放器按钮。
- 倒计时可以是视觉表现，但不等于真实超时逻辑。需要实际倒计时交互时先核验播放器能力；只对确实容易误生成 UI 的片段添加针对性限制。

写入前逐片段比对关键动作及顺序、逐字台词和画面文字、结束状态、参考身份与实际参数冲突。按故事 Patch 契约只写 `video_prompt`，保留剧情、分支、素材和已有视频，并回读验证仍待处理的文字、声音或时长限制。

例：剧情为手机消息“这个方案，简单改一下”，文件标有“修改意见”，主角说“你管这叫简单？”。提示词必须保留三处原文及发生顺序，不能只写“手机显示消息、文件落下、主角惊恐”。
