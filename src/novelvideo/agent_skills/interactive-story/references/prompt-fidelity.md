# 剧情到视频提示词的保真

适用于首次准备、批量改写及修正 video_prompt。先读取当前 script、production_notes、video_prompt、真实参考素材和节点参数；以用户最新确认的剧情为准。转换为可拍摄的镜头描述，不擅自改编剧情。

- 保留关键事件、先后顺序、人物意图和结束状态。“即将看消息”不能改成“已经看完并爆发”；汇合片段不能假定玩家走了某一前置分支。
- 对白、旁白、手机消息、标牌及字幕逐项核对，保留原文和说话人／呈现位置。不能把具体消息缩成“显示消息文字”，不能用表情替换对白。
- 区分剧情文字和玩家选项。默认使用播放器选项，但不是禁止生成视频内 UI。剧情字幕或手机文字不会因此自动叠加；没有已验证的后期文字功能时，不承诺后期自动补齐。在提示词中保留文字要求，并明确精确文字生成仍需成片核验。用户明确选择后期处理时，记录原文和位置为待完成项，不声称制作就绪。
- 可以补充景别、光线、运镜和参考用途，但不得引入改变情节的新动作或提前的情绪结果。不要让“夸张喜剧”等风格描述覆盖剧情要求。
- 用实际素材 mention 绑定身份、场景和产品；身份参考图片中的姿势／表情不覆盖本段动作。承接尾帧则明确该图片用于开头状态，后续动作从该状态自然发展，不能套用“姿势不参考”的统一说明。尾帧尚未产生时按 production-planning.md 先规划依赖、后绑定真实图片。只有文字元信息时，不声称已检查图片细节。
- 检查动作与对白能否装进当前时长。装不下时报告冲突，不静默删台词、增加定格或拆分剧情。仅修提示词时保留模型、时长、画幅和声音参数；发现冲突须报告，不能只在提示词写“竖屏”就宣称实际参数已改。

## 按片段用途描述 UI 与收尾

- 不给每段追加“画幅、时长及声音能力以节点实际设置为准”。这是执行者核验参数的规则，不是模型可拍摄内容；实际设置需在节点读取和应用。
- 只在需要停留选择或计划提供衔接尾帧时要求稳定收尾。普通转场按剧情继续，结局按广告收束意图结束；不统一追加“供播放器停留选择”。
- 允许用户希望的视频内装饰 UI，例如冰爽数值、漫画气泡、发光标签和夸张反馈。写明外观、位置和出现时机，不能用装饰数值冒充真实点击统计或玩法结果。
- 用户希望按钮视觉融入视频时，可以生成按钮外观。明确它本身不可点击；成片后需用现有“视频内 UI 热区”配置真实点击区域，并核验文字、位置、停留画面及竖屏适配。不要根据未生成画面编造准确坐标，不重复叠加同文案的可见播放器按钮。
- 倒计时可作为用户指定的视觉表现，但不能声称它已绑定真实超时逻辑；需要实际倒计时交互时先核验播放器能力。仅在确实需要避免误生成按钮的片段写针对性约束，不统一追加“不要生成互动按钮或倒计时”。

写入前逐片段比对：关键动作及顺序、逐字台词／画面文字、结束状态、参考身份、实际参数冲突。修复漏项后，按故事 Patch 契约只写 video_prompt；保留剧情、分支、素材和已有视频。回读验证，报告仍需处理的文字、声音或时长限制，不触发生成。

例：剧情为手机消息“这个方案，简单改一下”，文件标有“修改意见”，主角说“你管这叫简单？”。提示词必须保留这三处原文及发生顺序，不能仅写“手机显示消息、文件落下、主角惊恐”。
