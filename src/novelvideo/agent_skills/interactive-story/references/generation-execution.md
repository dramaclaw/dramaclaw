# 互动影游生成执行

仅用于用户已经批准制作方案并明确授权生成、继续或重做视频的请求。开始前读取 [production-planning.md](production-planning.md) 的逐片段就绪标准，并 Get 当前故事与受影响节点；不要仅凭提示词非空或制作备注宣称就绪。

## 提交范围

使用当前宿主提供的 `freezone_run_workflow`，并以实时工具契约为准：

- 本批生成或继续：只提交本故事中已准备、尚无视频且未在生成的真实视频节点 ID，使用 `node_ids=[...]`、`direction="node"`、`regenerate=false`，一次提交本批。
- 不使用全画布范围，不沿剧情选择线扩展节点，也不逐节点重复提交同一批。执行器只调度已经存在的媒体依赖，不会根据剧情边或制作备注自动创建依赖。
- 明确重做指定片段时，仅对已授权节点使用 `regenerate=true`。前片重做不会自动授权覆盖后片；先核对受影响的尾帧和参考版本。

各节点可以使用不同模型、时长、模式、声音和参考。依赖未就绪的片段等待下一批；无关且已就绪的片段可以独立提交。

## 状态、后续批次和失败

`awaiting_approval`、`accepted` 和 `running` 都不是完成结果。请求被接受后不重复运行，也不自行循环轮询；使用宿主返回的完成结果或可用状态入口核实。缺少结果时只报告“已提交”或“状态待核实”。

本批实际完成后，按 production-planning 的尾帧规则处理下游待衔接片段，重新完成就绪核验，再提交下一批。没有真实结果或必需素材时保持待准备，不承诺执行器会自动完善提示词。

媒体生成失败时停止相关执行并报告返回原因，不自动改提示词或重试。只有用户后续明确要求重试时，才开始新的生成请求；工具提供恢复能力本身不构成再次生成的授权。

批量执行只写入现有节点，不创建持久化的整部默认设置。新增片段需重新规划和应用参数，不得声称自动继承历史对话或同组设置。
