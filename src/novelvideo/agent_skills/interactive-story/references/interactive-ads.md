# 互动广告创作与交付

所有互动广告、交互式视频广告请求在提出方案前读取本文档，即使用户没有提到 CTA、长按或热点。广告采用这里的创作规则；共享主技能的故事写入、制作审核和生成授权流程。

## 按广告目标规划

从已有上下文提取产品、受众、核心卖点、目标动作和目标时长，只询问会实质改变方案的缺失信息。未确认的产品事实、参数或卖点标为待核实，不编造效果、性能或转化承诺。

先给可审核的自然语言方案，包含核心创意、用户动作、分支对应的展示内容、收尾以及可选 CTA。“开场吸引 → 用户选择或动作 → 对应卖点展示 → 收尾行动”是一种可选组织方式，不是固定模板。每个分支应服务于受众兴趣或卖点展示，也可以采用短汇合流程。

宿主使用结构化回复契约时，将完整自然语言方案放入回复的 `message` 字段；不要在 JSON 对象之外输出 Markdown。

广告不套用七片段、两个选择点和两个结局的影游默认值。根据内容、用户时长和模型实际支持的片段时长决定节点数量；没有必要时不增加游戏化结局。广告的收尾仍按故事契约使用 ending Segment。

分别报告单条路线的视频观看时长、交互等待时间和全部分支素材的制作总量。例如，15 秒广告的互斥卖点分支不能同时计入单次观看时长。模型尚未选定时给出估算，制作审核阶段按实际能力校正，不承诺未经核实的精确时长。

提案和写入前分别核对片段清单、每条路线秒数之和及素材总量；共用片段在制作总量中只计一次，等待循环素材另列，不把无限等待折算成固定秒数。创建必须保留获批的时长预算和交互结构；需要改成其他时长或增减互动时先说明差异并确认，不能仍沿用原时长标题。视觉创意也可能暗示产品性能（如瞬间静音、特定座椅布局），未确认时标为候选表现、待核实，不作为既有卖点。

仅要求方案时，在对话中给出方案并结束，不写画布或生成媒体。用户批准具体大纲后才创建故事；制作规划使用 [production-planning.md](production-planning.md)，提示词使用 [prompt-fidelity.md](prompt-fidelity.md)。生成仍需明确授权，并遵循 [generation-execution.md](generation-execution.md)。

## 可实现的互动

使用 click、hold、热点或选择循环时读取 [interaction-options.md](interaction-options.md)，按其中字段和片尾触发约束规划。用户要求“视频中间长按加速”等任意时刻互动时，解释当前限制，提出在动作节点拆段、片尾等待输入后继续展示的方案；取得确认后再调整故事结构。该方案不能被描述成已支持连续实时操控。

视频中生成的按钮是视觉内容；真实点击必须由播放器 Choice 或热点实现。方案应明确采用哪种交互，最终画面未产生前不编造热点坐标。

逐项区分预制画面表现与播放器真实行为：换色或加速可以设计为选择后播放对应预制片段，不能承诺片中实时换色、调速或持续操控。分段替代方案需说明选择发生在前片结束后，而不是在仍播放的视频上即时生效。

CTA 是可选项。没有 CTA 的品牌互动广告可以有完整收尾，不强制添加外链。有 CTA 时使用交互文档的字段契约；目标地址缺失则保留未配置草稿，明确该外链尚不可交付使用。只采用用户提供的真实 HTTPS 地址。

运行时 `dramaclaw:story` 事件只提供宿主集成 hook，不代表已有服务端分析；`cta_click` 仅表示点击，不证明表单提交、线索收集或转化成功。

## 按交付范围验收

- 方案交付：创意、用户动作、分支展示、收尾和时长预算清楚，产品事实待核实项已标出。
- 占位原型：故事写入和 Validate 成功；需要试玩验收时检查各预期分支能到达收尾、click/hold 与限时选择按配置工作。占位素材不代表正式广告视频完成。
- 成品交付：核对各路线实际播放、用户动作对应内容、收尾、画幅适配；有热点时核验最终画面中的位置、可点击范围和停留画面；有循环时检查切换和循环表现。
- 配置 CTA 时核对保存地址与用户提供地址一致，并在已授权的试玩范围检查链接行为；不提交落地页表单。未实际打开或验证时明确标记为未实测。

报告已完成项、未验证项和阻塞项。只有真实验证过的行为才能标为通过，生成任务被接受、静态文档检查或 Validate 通过均不能替代成品试玩。
