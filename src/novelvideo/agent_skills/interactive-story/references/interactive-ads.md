# 互动广告

提出互动广告方案前读取本文档；故事保存、阶段进度和生成授权沿用主 Skill。普通线性广告不进入此流程。

## 方案与时长

从上下文提取产品、受众、核心卖点、目标动作和目标时长；只集中询问会改变方案的缺失项。未经用户确认的性能、效果和视觉暗示都标为待核实，不编造转化承诺。

先给自然语言方案：核心创意、用户动作、各分支展示、收尾和可选 CTA。分支应服务受众兴趣或卖点，可短汇合；不套用影游约七片段、两个选择点和两个结局的默认规模。即使只有一个收尾，故事契约仍使用 ending Segment。保存待确认大纲时 `kind=ad`，按单条路线填写时长预算；只要方案时不保存、不生成。

分别估算每条路线的观看时长、交互等待时间及全部分支素材的制作总时长。互斥分支不同时计入单次观看，共用片段在制作总量中只计一次，开放等待不折算成固定秒数。模型未选定时给估算，审制作时依当前模型能力校正。若需改变已获批的时长或交互结构，先说明差异并确认。

## 交互与素材

click、hold、热点和选择循环按 [交互选项](interaction-options.md) 设计；现有选择在片尾激活，不支持视频中任意时刻的连续换色、调速或长按控制。可经用户确认拆成“前片结束 → 选择 → 对应预制片段”。视频里画出的按钮只是画面，真实点击须由播放器 Choice 或热点实现；最终画面未知时不编造热点坐标。

CTA 可省略。有 CTA 时只用用户提供的真实 HTTPS 地址；地址缺失可保留未配置草稿，不称为可用外链。`cta_click` 仅证明点击事件，不证明表单提交或线索转化；`dramaclaw:story` 事件是宿主集成 hook，不等于服务端分析。

广告与影游共用创作阶段。跨片段保持外观的品牌角色或重复场景，在写逐片段提示词前按 [制作规划](production-planning.md) 整理真实参考素材；不能由角色定义、文件名或后续视频节点推断角色／场景阶段已完成。纯产品特写或一次性出镜可不建独立角色／场景资产，说明原因即可。

## 交付核验

占位原型需故事写入和 Validate；要求试玩验收时检查预期分支、手势及限时选择。成品需实际核对路线播放、互动内容、收尾与画幅；热点检查最终画面的区域，循环检查切换。有 CTA 时核对保存地址及已授权范围内的点击行为。未实测的项目明确标出；生成接受、静态校验和 Validate 均不代替成品试玩。媒体提交按 [生成执行](generation-execution.md)，逐镜头提示词按 [提示词保真](prompt-fidelity.md)。
