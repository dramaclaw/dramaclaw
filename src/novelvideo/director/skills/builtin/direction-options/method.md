# direction-options — host-adapted method 2.3.2

Confirmed parameters and locked facts override all generic references: no mandatory 50-100 episodes, paywalls, four villain levels, repeated hook, or extra scenes. Never claim measured duration, approval, complete source audit or full TV Director parity. Questions and risks must be explicit. Return only the exact responseSchema JSON. All technical IDs use ASCII, e.g. option-1 and question-1; prose uses the requested language.

Create four substantively different directions for the supplied brief. For each give a visible goal, obstacle, stakes, tone, a concrete difference from the other options and production risks. Preserve confirmed genre, duration, episode count, ending, language and locked facts. Do not produce the full screenplay. Human selection or a free-form direction is required before any preparation. Titles alone do not distinguish directions.

For original creation, return specQuestions as an empty array. The host asks the human to confirm or change episode count and per-episode duration after choosing a direction; never invent additional compulsory questionnaire pages or decide those numbers from the story. Put useful uncertainty in the direction's productionRisks without promoting it to an established plot fact. A user may add a specific creative constraint in the free-form direction field.

For adaptation, read the full sourceText before proposing directions. Four directions are different ways to TELL THIS story (viewpoint, emphasis, atmosphere, information release), not four replacements for its events. A locked chronological order rules out flashforwards/reordered scenes. Never substitute a familiar version from memory. Preserve named actors, actions, rescue and ending. Identify missing action bridges and competing character claims BEFORE drafting the outline. Each consequential gap becomes a concrete specQuestion, with up to six concise choices when useful; always allow free-form answers. At least one choice can preserve ambiguity without adding an event. Do not offer a new cause or rule as already confirmed, and do not ask the user to reconfirm facts clearly supplied. Use questions to give the user control, not to force changes to count, duration or the source.

Before asking, distinguish an unresolved choice from an explicit user policy: "leave the cause unknown" already resolves how to adapt it. Do not reopen that choice, repeat configured count/duration, or offer a reordered version when chronology is locked. If no consequential choice remains after reading the brief and source, return specQuestions as an empty array. The direction selection itself still provides human control.

Output contract: the root has exactly options and specQuestions. Each of the four options has exactly id, logline, goal, obstacle, stakes, tone, difference, productionRisks. Put qualifications inside the relevant prose or productionRisks; never create alternative, note, placeholder or correction keys, even with empty values. Each question has id, question and optionally choices. Return one complete object, with substantive sentences rather than schema examples or a second corrective draft.
