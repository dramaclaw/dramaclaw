# 互动故事制作规划

用于整部或指定片段的素材、参数、承接、提示词和就绪检查。制作方案及参数写入不授权媒体生成；生成前再读 [生成执行](generation-execution.md)。局部请求只检查涉及的片段。

## 读取与规划

先 Get 故事和画布，用真实关联找到各 Segment 的视频节点；剧情关系以故事为准，参数和引用以 `freezone_get_node_detail` 的 `parameters`、`reference_media` 为准。需要动作能力时读 `freezone_get_node_action_catalog`。收集已有视频、提示词、`model`、`genMode`、`durationSec`、`aspectRatio`、`quality`、`generateAudio` 和已连接素材；模型与时长档位、参考类型/数量、声音及清晰度按当前 options 核对，不从标题或记忆推断。

制作影游素材前，先在 StoryDraft 写好 `characters`（人物、产品主角、重要物品）、`scenes`，并逐片段填写 `character_ids` 与 `scene_refs`。每个主体/场景使用稳定 ASCII ID；明确其视觉描述和使用片段。故事 Patch 完成后再提交图片工作流。工作流 `source_context` 使用 `story_id` 和 `asset_targets`：每张图片声明 `plan_node_id`、`kind: "subject"|"scene"`、`entity_id`、`segment_ids`。服务端会核对所有目标片段确实在当前故事中要求该主体/场景；生成成功后宿主再按当前规划回连。`product` 主体也用 `kind: "subject"` 的目标。分镜开场图继续使用 `targets` 的片段映射，两类目标不要混用。没有规划的旧故事可保留人工连线，不会自动猜测分配。

集中给用户“审制作”摘要：主要路线观看时长、公共模型/画幅/声音、所需人物和场景、逐镜头例外及待补项。跨片段整理角色、场景、物品的稳定外观与状态，区分已有、待提供、待制作素材；文字设定不等于真实图片。分支汇合应兼容所有来源。未获用户要求时不逐项追问资产或逐节点配置。

观看时长按起点到结局分别估算，互斥分支不相加；全部分支素材制作总时长另算。开放等待、倒计时和选择循环与主视频分开；有条件路径或循环时说明估算覆盖范围。片段时长优先使用配音实际长度，否则按对白、动作、读字和停顿估算，并匹配模型档位。装不下时提出简化或拆镜建议，未经同意不改剧情结构。模型、画幅、清晰度可共用；`durationSec` 必须逐视频节点确定，不使用全片共享时长。

`script` 保留剧情，`production_notes` 记录场景、人物、动作、镜头、声音及首尾连续性，`video_prompt` 只描述本镜可拍内容，不写条件、变量或路由。准备提示词时再读 [提示词保真](prompt-fidelity.md)。

## 参考与承接

- 剧情 Choice 线不是媒体参考。按不同前置视频计数；同一视频的多个选项只算一个来源。单一前镜、同场景连续动作可用 `continuityMode=auto`；起点、换场、跳时间和多来源汇合默认 `independent`。多来源汇合仅在用户点名来源时设 `continuitySourceNodeId`，否则用兼容所有来源的开场。
- 审核时逐镜头给出承接模式、真实来源、前镜收尾和后镜开场。来源未生成时标待生成，不编造尾帧 URL 或素材 mention。需要先承接尾帧再换场时可设 `auto`，但提示词须描述可见转场。`continuityMode` 是视频节点字段，不写 StoryDraft。
- 自动承接在生成入口提取或复用实际前镜尾帧，同源分支共享截图，并按依赖顺序运行；源视频换版只在下次生成下游时更新参考，不自动重做成片。切回独立开场时，宿主清理旧自动承接引用。多图参考不能保证严格首帧一致，自动承接也不等于目视检查已完成。
- 自动承接只处理尾帧。额外人物、场景、产品图须是真实图片节点，以 `media_input_for` 连到目标视频并回读 `reference_media` 与视频节点当前 `prompt`。素材连线和提示词中的 `@图片N` 是两项独立检查：只看到连线不能宣称提示词已引用。宿主会按真实连线补齐视频节点缺失的素材 mention；如果回读时仍缺失，标记待修复，不宣称已完成。只有 `continuityMode=auto` 且前镜已完成时，生成入口才写入实际尾帧说明；剧情文案或自动剧情线不能代替这个字段。未连入的图不能当作引用，编号不能预写。
- 首帧模式只接受一张开场图；多图需求选支持多图的模式或经确认合成开场图。全能参考不保证严格复现。汇合片段不任取一条路径尾帧，也不批量添加多条视频媒体依赖。

需要提前审查或单独截帧时，先查来源视频动作目录。支持 `capture_video_last_frame` / `capture_video_first_frame` 才用 `run_node_action`，然后回读图片节点、来源视频 URL/版本并按已批准用途绑定。缺少动作时标待人工处理；只有元信息时不声称看过画面。源视频换版后重核受影响的手动尾帧；未开启自动承接时，剧情线本身不会建立媒体依赖。

## 应用与就绪

确认方案后，先回读最新故事、画布、节点和模型目录，再写逐镜头参数；复用已生成图片，缺分镜图时按 [分镜图批量制作](storyboard-frames.md) 建组并待其完成；将本镜需要的人物、场景和产品图连入视频，回读真实引用和宿主补齐的素材用途，再提交就绪视频。

- 单节点参数用 `freezone_update_node_data`。多节点先读命令契约，再用一次 `freezone_emit_canvas_command` 的 `canvas_chat_commands.v1` 批次，各 `update_node_data` 指向真实 `node_id`。字段用 `model`、`genMode`、`durationSec`、`aspectRatio`、`quality`、`generateAudio` 和已确认的承接字段，不把 API 字段 `durationSeconds`/`resolution` 写入节点或 StoryDraft。
- 素材连线只按已批准方案创建或替换，之后回读 `reference_media` 的真实顺序和 mention。剧情与镜头动作提示词用 Story Patch 的 `update_segment.changes.video_prompt` 写入；同阶段多个片段合并一次 Patch，保留剧情、分支、媒体和用户新编辑。宿主按真实连线补齐缺失的素材 mention 与用途，Agent 不预写编号或复制托管素材段。尾帧到位后可在新阶段再次 Patch，但先 Get 当前故事。画布多步写入不是事务，失败时按回执确认已应用项。
- 宣布“可生成”前逐镜头确认：时长符合当前模型能力，首尾和汇合状态兼容，必需参考真实可用且视频 `prompt` 中有与实际顺序对应的 `@图片N`，自动承接已在视频节点回读到 `continuityMode=auto` 和正确来源，手动尾帧来源版本正确或自动承接的上游已完成/在授权批次内，参数、提示词与引用均已回读。缺项保持待准备；不要把生产备注当执行指令，也不存在持久化的整部默认参数自动继承。
