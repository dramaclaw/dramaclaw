# 互动影游制作规划

用于整部影游的制作准备、统一模型与逐片段时长规划。复用虾塘资产、现有节点参数和提示词；不新建资产库、设置页面、故事结构或隐式的全局默认字段。

## 读取现状

先 Get 故事和当前画布，将 Segment 对应到真实视频节点。剧情关系以故事工具为准，实际生成参数、已连接素材以节点详情为准。使用当前会话暴露的 `freezone_get_node_detail` 读取 `parameters`、`reference_media`；需要动作参数时读取 `freezone_get_node_action_catalog`。不能从标题推断节点 ID、模型 ID 或素材用途。

收集：已有视频、当前提示词、model、genMode、durationSec、aspectRatio、quality、generateAudio，以及人物、场景参考是否就绪。模型必须从当前动态 options 选择；核对模型的参考类型、数量、声音、时长范围及可用档位。不凭记忆指定模型能力或价格；无法读取能力时将该项列为待核实。

## 提出计划

默认整部共用一个模型、画幅和清晰度，但保留用户明确指定的例外。优先满足已选人物/场景素材、声音和镜头需求；没有共同可用的模型时，解释具体冲突并提出最少的例外，不静默替换用户模型。

逐片段安排时长：优先使用已有配音的实际时长；否则按对白自然语速估算，列出主要动作、画面文字阅读、表演停顿及收尾的时间顺序。对白与动作同时发生时按重叠时间安排，不重复相加；先后发生的事件需留足时间。注明是估算，不能把长对白机械塞进默认 5 秒。玩家等待选择不计入主视频时长，普通转场和结局不自动增加选择定格。将估算匹配当前模型实际支持的时长档位，并核对节点设置；若超过模型能力，提出简化镜头或拆分建议，未经同意不拆剧情节点，也不依赖前端静默限幅。

参考规则：
- 明确选用已有虾塘人物图、场景图；人物身份记录本身不等于已绑定参考图片。只规划真实可定位的素材，缺少的列为缺失项，不自动创建或收费生成。
- 剧情选择线不构成媒体参考。按不同的前置视频节点数判断汇合，多个选项来自同一个视频只算一个前置来源。
- 单一前置视频且同场景连续动作，可提议将其尾帧作为本片段首帧；截帧未完成时标为待准备，不声称已有首帧输入。
- 多个不同前置视频汇合，默认人物/场景参考加共同可衔接的开场构图，不任意选择某条路径尾帧，不创建多套衔接版本。
- 首帧模式只接受一张开场图。人物图、场景图加尾帧不能直接一起塞入首帧模式；需要多份素材时，提议支持多图的参考模式，或先制作合成开场图。全能参考不保证严格从某张图片开场。

输出一份紧凑清单：片段、建议秒数及依据、模型/生成模式、参考素材及用途、缺失项；公共画幅/清晰度/声音策略写在表前。标出与当前设置的差异及已有成片。向用户确认这份具体计划；已有明确授权且具体参数已确认时不重复确认。准备计划不是执行生成。

## 尾帧分两阶段准备

规划阶段不需要已有尾帧图片。逐片段注明“独立开场／承接指定前片尾帧／多路汇合共同开场”，记录真实来源节点、预期收尾状态及后片从该状态开始的动作。来源未生成时，将尾帧标为“待前片生成后提取”；可以准备提示词草稿，但不编造素材 URL、mention 或已就绪状态。这些是制作计划信息，可按授权写入现有 production_notes，不创造未经契约支持的字段或自动执行机制。

生成准备阶段按顺序处理：
1. 读取来源视频当前选用的成片版本，使用现有可用截帧能力取得真实尾帧；工具不支持时明确待人工截帧，不声称已自动完成。
2. 检查尾帧实际构图、姿势和道具是否符合衔接意图。明显偏离剧情时说明冲突，不靠提示词强行宣称无缝衔接，也不擅改剧情。
3. 按已确认模式绑定尾帧，并重新读取真实素材 mention。全能参考中明确区分“尾帧用于开头画面”“人物图用于身份”“场景图用于环境”；描述从尾帧状态开始的连续动作，避免开场立刻重置机位或姿势。全能参考可以引导开场，仍需成片核验，不承诺像素级复现。
4. 依据实际尾帧完善后片提示词，核对时长和节点参数，再报告是否可生成。执行生成仍需已有生成授权；未准备好的依赖片段保持待准备，无关片段可独立准备。

来源视频重新生成或切换版本后，核对原尾帧是否过期并提示受影响片段。未经授权不替换已绑定的参考、不重新生成下游。剧情连线不自动成为媒体依赖；当前执行器可为实际视频 `dependency_for` 输入提取尾帧并连接图片；这不适用于普通剧情选择线，也不代表会根据制作备注自动建依赖或处理来源版本失效。只在已确认的单来源连续镜头且工具契约支持时使用该依赖，汇合片段不批量添加多条视频依赖。

## 确认后应用

重新读取受影响节点，核对用户期间的修改；发生冲突时保留新改动并说明，不用旧计划覆盖。只写已批准的字段和片段。

- 单节点参数使用 `freezone_update_node_data`；多节点使用命令目录支持的 `freezone_emit_canvas_command`，一次 `canvas_chat_commands.v1` 的 `commands[]` 批次，每项 `update_node_data` 写真实 node_id 和 data。先读取命令契约并按要求校验，参数以节点 `parameters` 为准。
- 将模型写入 `model`、模式写入 `genMode`、时长写入 `durationSec`、画幅写入 `aspectRatio`、清晰度写入 `quality`、声音写入 `generateAudio`。不要把 API 请求字段 `durationSeconds`/`resolution` 写入节点；不要把这些字段塞入 StoryDraft 或只写进提示词。
- 素材引用的创建或替换仅在计划已明确批准时执行，遵循现有连接工具契约；缺失输入的片段保持待准备，不能宣称整部已就绪。
- 设置成功后重新读取实际素材编号，为就绪片段准备提示词。使用 `reference_media` 中的准确 mention 与用途，不自行编号，不把旧的失效 @引用带入。只依据素材元信息时，不声称已看清图片细节。
- 提示词按现有故事 Patch 契约，通过 `update_segment.changes.video_prompt` 写入；同一准备阶段合并多个片段为一次原子写入。取得新尾帧等后续阶段可在已有授权范围内再次写入，但每次先 Get 最新版本，保留 script、已有 media、剧情分支和用户编辑；不重复提交成功或结果不明的写入。
- 多步写入不是事务。逐阶段确认结果；失败时报告哪些已应用、哪些待处理，不盲目重放整个批次。回读验证实际参数与引用，不能仅凭生成文字宣称成功。

报告“已规划／参数已写入／提示词已准备／素材待补齐”，与“已生成视频”区分。不要触发 run、实时生成或任何收费任务，除非用户另外明确要求生成。

## 执行边界

故事批量生成入口复用现有工作流执行器，只提交该故事中提示词非空、尚无视频且未在生成的节点，使用逐节点模型、时长、模式、声音与参考。它不读取制作备注来自动设置参数，也不能把备注里的“待尾帧”视为已经绑定的依赖。用户要求生成时，先核验参考和依赖已实际准备好，不能只看提示词非空就宣称就绪。

本阶段是批量写入现有节点，不新增持久化的“整部默认设置”机制。用户以后增加片段时，读取已确认计划及现有同组设置，提出新片段的参数并按授权应用；不要声称新节点已自动继承，或仅凭历史对话覆盖它。
