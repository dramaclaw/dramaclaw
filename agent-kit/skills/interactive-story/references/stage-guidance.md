# 创作阶段与下一步引导

故事 Create/Validate 成功后，以及用户问“下一步”、完成一项工作或要求确认阶段时，调用 `dramaclaw_get_interactive_story_progress`。以返回的 `current_stage_id` 为最早未完成项，结合 `stages` 和 `evidence` 说明：目前已完成什么、这一项还缺什么、用户现在可做的一个具体动作。不要仅凭聊天记忆、节点标题或截图推断状态；不要跳过 `manual` 阶段，将后面的“视频”说成当前阶段。局部编辑仍按用户指定范围执行，阶段引导只用于交接。

| 当前阶段 | 给用户的下一步 |
| --- | --- |
| `proposal` 策划案 | 尚无大纲时，补齐会影响方向的偏好并给可审核的创意、分支与单路时长；已有 `pending/needs_revision` 大纲时，指引用户审阅或修改画布方案卡，不重复从零策划。只要方案时止于对话。 |
| `outline` 大纲 | 若有待确认大纲，指引用户在画布方案卡审阅、确认或要求修改；未确认前不创建正式故事。 |
| `script` 剧本 | 根据缺失片段文案和 lint 错误补剧本、修断链，再 Validate；指出具体片段。 |
| `characters` 角色 | 说明已有哪些角色定义、哪些跨片段人物还缺外观设定或参考素材；请用户审阅角色一致性，确认已完成或明确要求先跳过。`character_count` 不是角色素材完成证明。 |
| `scenes` 场景 | 整理重复场景和换场所需的视觉锚点，区分已有/待提供/待制作素材；用户要求创建时制作实际场景参考图，核实画布节点及生成结果；请用户确认场景方案已满足当前故事，或明确要求跳过。无需强制每个片段单建场景资产。 |
| `storyboard` 分镜 | 给逐片段构图、时长、承接及必需参考的方案；缺图时按 [分镜图批量制作](storyboard-frames.md) 准备并核对结果。请用户审阅分镜后确认完成或明确要求跳过；图片节点存在不等于分镜图已生成。 |
| `video` 视频 | 用 `video_ready_count/segment_count` 说明真实成片进度，列出缺视频或失败的片段；先审制作并核验参数、素材和提示词。仅在用户明确授权生成后按 [生成执行](generation-execution.md) 提交，任务 `accepted/running` 仍未完成。 |
| `complete` 完成 | 引导实际试玩主要分支、结局、选择和媒体衔接，核对交付内容；Validate 只是结构检查。用户确认验收完成或明确要求越过此人工阶段后，才记录完成；跳过时标明未实测。导出或发布另按用户请求处理。 |

`characters`、`scenes`、`storyboard`、`complete` 的 `manual` 表示没有可靠自动完成判据，不是报错或“不适用”。Agent 可帮助准备产物，但不能自行把 `manual` 说成 `done`。用户明确说某人工阶段已完成，或明确要求越过它继续时，先回读当前故事和 revision，调用 `dramaclaw_confirm_interactive_story_stages(action="confirm")`，收到成功回执后再 Get progress 并引导下一项；用户要求返工时用 `action="reopen"` 并回读。仅说“下一步”不等于确认，也不授权付费生成。

“直接创建场景/角色”要求制作产物，不表示“该阶段已完成”或“跳过”。先读故事与现有素材，合并复用的场景；缺少的场景参考图走 `text-to-image-video` Workflow Skill 的 `general-image` Recipe，按工作流草稿和画布确认入口创建／生成，已有图直接复用。若此前误确认了场景阶段而用户指出实际场景缺失，先用 `action=reopen` 纠正状态。若只能准备草稿、尚未落图或生成仍在运行，就如实报告该状态；不能用文字描述、阶段确认工具或进度查询冒充创建。创建后回读画布核实实际图片，再询问用户是否满足本故事的场景需要；没有用户明确确认或跳过时保持 `scenes=manual`，不要直接转入分镜。

例如前六项已完成、`video` 是 `todo`、`complete` 是 `manual`：应说“下一步是视频：先核对每段时长、参考图和提示词；您确认制作方案并授权后可生成缺失片段。成片后需要实际试玩，再确认完成阶段。”不要提前要求用户确认“完成”。
