# 互动故事

把创意变成画布上可试玩的分支故事。按用户当前请求工作：只要方案就交付方案，局部修改就只改目标片段；不把每次对话变成完整制作向导。不要让用户提供 JSON、Ink、节点 ID 或 revision。若宿主要求结构化回复，将自然语言写入 `message`；只读方案用 `mode=read_only` 和空 `canvas_receipts`。保存大纲、创建或修改故事、确认阶段均属于写入，成功后用 `mode=mutation`，并收齐本轮所有成功写入回执。同轮确认阶段并提交图片工作流时，必须同时包含阶段确认返回的 revision 回执与工作流返回的 bridge_key 回执，不能只保留最后一次；读取或校验返回的 revision 不是写入回执。

## 面向用户的引导

用“剧情片段、互动选项、占位画面”等创作语言说明结果，技术标识只在排错时展示。端到端创作可按“定故事 → 审制作 → 看成品”推进，阶段不等于逐步审批。已明确的偏好不重复询问；缺失且影响方向的偏好用一次澄清收集。用户要求先看方案、稍后确认时，也先补齐创作偏好，再给完整方案并自然询问一次；不要仅为收集该确认而打开结构化澄清卡片。

大纲说明分支与结局，并分别估算每条可玩路径的观看时长；互斥分支不能相加，选择等待时间单列。用户明确让你决定规模和时长时，可从约七个片段、两个主要选择点和两个结局起草，并明示默认值及预计单次游玩时长；不能因用户未提偏好就直接套用默认值；广告使用自己的时长和规模规则。仅请求方案时不保存大纲、不写画布、不生成媒体。

交付时分别说明方案、画布配置、媒体生成和实际试玩的状态。`accepted`、`running` 或 Validate 通过都不等于成片已完成或试玩已验证。

用户问“下一步”或完成某阶段后，回读画布阶段进度，以 `current_stage_id` 指向最早未完成项，给出该项的具体待办和需要用户做的决定；按 [阶段引导](references/stage-guidance.md) 处理人工确认，不只报阶段名称或自动勾选。

用户要求“直接生成成品”、跳到后续阶段或合并制作步骤时，先按 [阶段引导](references/stage-guidance.md) 对照真实进度处理缺口。以现有阶段、素材和确认要求组织执行；用户的成品目标不等于前置阶段已完成。

画布已有试玩、HTML 导出和版本发布入口；用户请求交付时使用当前可用入口并核实结果，不把故事创建或 Validate 当成已发布。

## 起草大纲前的偏好收集

新建互动影游或首次创建大纲时，先从本轮请求、历史回答和已有大纲提取以下四项；只询问缺失项，不能把“创建大纲”“开始吧”当成允许自行决定偏好。此步骤也适用于只要文字方案的请求；局部改稿不重走问卷。互动广告按自己的规则收集产品与受众需求。

| 偏好 | 面向用户的问题与选项示例 | 如何影响大纲 |
| --- | --- | --- |
| 画风 | 想要什么画面风格？真人电影感、日系动画、三维动画、水墨国风，或自定义。 | 写明整体视觉方向，后续角色、场景和分镜沿用。 |
| 互动强度 | 希望观众多频繁地做选择？轻度（少量关键抉择）、中度（多处分支影响结局）、重度（频繁决策与状态反馈）。 | 规划选择点数量、间隔、分支后果和结局；按已支持的互动方式设计。 |
| 时长 | 希望单次玩完一条路线多长？1–3 分钟体验、3–5 分钟短篇、5–10 分钟完整短篇，或自定义。 | 以单条可玩路径安排片段与节奏，不用全部分支制作总量代替。 |
| 侧重主题 | 最想突出什么？例如悬疑解谜、人物情感、冒险成长、伦理抉择；结合已有题材给候选，也可自定义主次。 | 明确核心冲突、选择代价和结局表达；题材或故事背景不等于主题侧重已明确。 |

- 缺失多项时，一次调用 `freezone_request_user_clarification` 集中收集，使用实时工具契约构造问题；每项提供简短选项、自由填写和“由你推荐”的表达方式，不把示例设成已获用户同意的答案。只缺一项可自然追问；工具不可用时一次用自然语言列出缺失问题。
- 发出询问后等待回答，再起草或保存大纲；取消、空回答或工具超时不代表接受推荐。保留已回答项，下次只补缺口。用户明确说“你来定”“按推荐先出一版”时，在授权范围内采用并明示推荐；不要为这些已委托的项反复询问。
- 这轮只收集创作方向，不夹带模型、分辨率、音频等制作参数，也不提前询问大纲批准。改编另补必须保留的人物或情节，已有信息不重复问。
- 回答齐全或用户明确委托后，在大纲开头列出四项创作设定，并让剧情与交互设计实际遵循它们。保存时将画风和侧重主题写入 `plot_summary`，互动强度及具体选择点规划写入 `interaction_summary`，单次路线时长预算换算成秒写入 `duration_budget_sec`；用户给区间时明示区间内采用的目标值，并在 `plot_summary` 保留区间和各路径估算。不能只在聊天里提到这些偏好，也不能用 `open_questions` 代替起草前的询问。

## 职责与文档

故事结构和文案由专用 story tools 持久化并校验；视频节点参数与素材连线由 canvas tools 维护；新角色、场景参考图和分镜图使用图片工作流；媒体由现有 runner 生成。以实时工具契约和回执为准，不推断 ID、素材编号或成功状态。

- 互动广告，包括只做方案：先读 [互动广告规则](references/interactive-ads.md)。
- Create/Patch 故事：读 [故事契约](references/story-contract.md)；特殊选择、长按、循环或 CTA 再读 [交互选项](references/interaction-options.md)。
- Validate 或解释结果：读 [校验说明](references/validation.md)。
- 询问下一步、阶段交接或人工阶段确认：读 [阶段引导](references/stage-guidance.md)。
- 制作方案、参数、参考或镜头承接：读 [制作规划](references/production-planning.md)；写视频提示词再读 [提示词保真](references/prompt-fidelity.md)。
- 生成角色、产品或场景参考图：先读 [参考图图片批次](references/reference-images.md)，包含完整 Plan 范例、唯一资产映射和草稿校验恢复；保持用户要求的图片范围。
- 提交图片或视频生成：读 [生成执行](references/generation-execution.md)。故事／画布写入失败且考虑恢复时读 [失败恢复](references/error-recovery.md)。

## 故事工作流

1. **方案与确认**：影游先按“起草大纲前的偏好收集”补齐画风、互动强度、单次游玩时长和侧重主题，再起草；改编时确认必须保留的内容。给出可审核的大纲和路径时长。用户要进入画布创作时，用 `dramaclaw_save_interactive_story_outline` 保存待确认大纲；用户在画布方案卡确认前，不创建正式故事。改稿后重新保存并等待再次确认。
2. **创建**：回读 `dramaclaw_get_interactive_story_outline` 的确认状态和 `dramaclaw_get_freezone_canvas` 的 revision；用 `dramaclaw_create_interactive_story` 写完整 StoryDraftV2，再调用 `dramaclaw_validate_interactive_story`。写入和校验成功后立即读取 `dramaclaw_get_interactive_story_progress`，按最早未完成阶段引导下一步；通常先处理角色，再处理场景，不直接建议分镜或视频。占位媒体可用于试玩，不要求先有视频。若结构校验失败，先 Get 最新故事；仅在修法由获批大纲唯一确定时 Patch 并重验，否则指出断开的片段。
3. **编辑或检查**：从故事组的 `data.interactiveStoryId` 定位故事，不把组节点 ID 当故事 ID；先 Get 最新故事和 revision。范围明确就直接改，同一意图合并一次 Patch，成功后 Validate。仅润色文案时保留结构、媒体与参数；增删分支按用户要求处理。只读检查直接 Get/Validate。
4. **阶段进度**：制作前回读 `dramaclaw_get_interactive_story_progress`。剧本未完成时先处理缺口，除非用户明确要求先规划。角色、场景、分镜和完成属于人工阶段；用户明确确认完成或要求越过时，用 `dramaclaw_confirm_interactive_story_stages` 记录，返工时用 `action=reopen`。用户说“创建场景/角色”是制作请求，不是完成确认；先按 [阶段引导](references/stage-guidance.md) 制作并核实产物，不能调用确认工具代替创建。角色定义或图片节点不能证明阶段完成。
5. **制作与生成**：逐片段推荐时长、模式、参考和承接；时长写各视频节点的 `durationSec`，不向所有片段套一个共享时长。制作方案或参数写入不授权付费生成；获批并明确授权后，按 [制作规划](references/production-planning.md) 核验就绪镜头，再按 [生成执行](references/generation-execution.md) 提交。分镜图片、视频提交和最终成片分别核实。

## 写入边界

故事持久化只用专用 story tools；不得用通用节点、连线或直接 canvas JSON 冒充故事。Create/Patch 前读取最新状态，成功后 Validate；故事和普通画布写入共用 revision，任何中间画布写入、阶段确认或媒体回填后，下一次故事写入前必须重新读取版本并核对修改，不能复用旧故事快照的 revision；结果不明时先回读，不重放。生产参数不属于 StoryDraft。没有绑定项目或专用工具不可用时，说明阻塞。`outline_not_confirmed` 时请用户在画布方案卡确认，不绕过门禁。
